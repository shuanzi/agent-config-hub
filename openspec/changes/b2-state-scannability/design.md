# Design: b2-state-scannability

## Context

动机与范围见 proposal.md。痛点主轴经用户确认为：**启用状态为主**（逐行辨认 4 个 toggle 无法回答"这个 skill 在哪些 Agent 上活着"），**来源状态为辅**；健康状态的现有 meta 表达已够用，明确移出本轮。当前形态：throwaway Mock 承载 selected B2；Skills 行内为 4 个一组的 toggle（点亮/置灰/dashed 三态已在本年 08-04 的 polish 轮确认）；规模预期几十项，全部状态为内存合成。

## Goals / Non-Goals

**Goals:**

- 每个 Agent 的启用状态形成一条可垂直扫描的固定列。
- 项目自有／全局适用的来源边界在快速滚动中可辨。
- 内容型资产选中即读、选中即改，窄屏无损退化。

**Non-Goals:**

- 不做独立"健康状态列"与六态词表组件（现有 meta 表达保留）。
- 不做 Agent × 资产独立矩阵视图、不做 `n/4` 计数摘要（均被分列扫描线取代）。
- 不做状态聚合 dashboard／待处理队列（规模不需要）。
- 不改动资产身份、作用域、授权模型、review/confirm/apply 状态机、全局搜索、toggle 三态语言本身。
- 不为分列或 master-detail 引入新的响应式断点。

## Decisions

### D1: Agent 状态拆成 4 个固定窄列，而非保留行内 toggle 组

行内 toggle 组里，同一 Agent 在不同行的水平位置虽然一致，但"组"作为整体与前后列共享空间，视线会被行宽变化（名称/路径长度差）干扰；独立窄列把每个 Agent 的状态钉在表头正下方的一条竖线上，扫描成本从"逐行解析组内第 N 格"降为"沿列扫"。这本质上是把矩阵思维折叠进表格，而不是新开矩阵视图（矩阵会牺牲路径、版本等行信息，且启停只是中频操作，不配独立视图）。备选：`n/4` 计数摘要——拒绝为并列方案保留，计数回答"几个"但回答不了"哪几个"，且给每行再加一个阅读元素。

### D2: 列头用品牌 Logo + 可访问名称

列头空间窄（每列约 40–56px），文字列头会迫使列变宽、挤压路径列。品牌 Logo 是本轮已确认的资产语言，配 aria-label/title 保证可访问性。风险是四个 Logo 的首次识别成本——接受，因为 toggle 单元格本身就在用同一组 Logo，列头与单元格互为图例。

### D3: 来源区分靠"分段层级 + badge 专色"，不加新控件

分段标题提升到"低于表头、高于行 meta"的中间层级（本轮 polish 已做第一步：加深 + 全局段蓝色）；badge 两种来源固定专色且不与状态/启停用色冲突。备选：加来源筛选器或来源列——拒绝，筛选解决"找"，不解决"扫"；独立来源列会再占 60px+ 横向空间，badge 已在承担该语义，问题是权重不足而非位置不对。

### D4: 内容型 master-detail 是主表面切分，不是常驻检查器

列表区与内容区同属主表面，共享同一份选中态；不复活 v22 移除的第四栏检查器。仅长期指令与 Subagents 启用；Skills 保持跳板模型。这是对 v22 决策的有记录例外，需在 UI_CHANGE_IMPACT 与基线验收表达中显式登记。

### D5: 窄屏双向退化，复用现有路径

Agent 分列在窄屏退化回行内 toggle 组（沿用现有窄屏卡片行）；master-detail 退化为现有"列表 → 详情"单表面栈。两条退化都不新增断点或第二路响应式逻辑，dirty guard、Esc、焦点恢复沿用已验证路径。

## Risks / Trade-offs

- 4 个固定列最小宽度合计挤压路径列 → 每列 40–56px、Logo 18px；1280 档可回落为 2×2 分组（现有 media query 已有此模式），验收线：路径折行不超过两行、toggle 列不横向溢出（L2 已有几何断言，沿用并扩展到分列）。
- Logo 列头的首次识别成本 → 列头 Logo 与单元格 Logo 互为图例；hover 提供文字 tooltip（title）。
- 分列后单击目标从"组内大格"变为窄格 → 保持单元格全高可点，命中区不小于 40×28。
- master-detail 让"当前选中"成为持久视觉态 → 选中态接入既有 `data-b2-focus` 焦点归还机制，不做新机制。

## Open Questions

- 内容型列表区是否显示内容首行摘要（帮助区分同名 AGENTS.md）——Mock 阶段用真实密度数据试读后再定，不影响 specs 与任务拆分。
