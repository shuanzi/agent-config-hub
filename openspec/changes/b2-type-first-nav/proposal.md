# b2-type-first-nav

## Why

正式产品基线 4.3 规定"资产类型优先、上下文感知"：一级导航固定为资产类型，用户无需先选择项目即可查看全部同类资产；项目/作用域是筛选与分组维度。当前 selected Mock 的"上下文 → 类型"两栏是 v22 的候选偏离（UI-B2-01，至今 pending）。本轮把 Mock 拉回基线：类型优先不仅与正式基线对齐，也让刚落地的内容型 master-detail（类型选择持久化、右侧内容区不跳动）和来源区分（badge/分段成为来源主表达）各就各位。

## What Changes

- 两栏对调：第一栏改为资产类型（Skills／长期指令／Subagents），第二栏改为作用域选择器（全部／全局配置／各受管项目）。
- 第二栏默认选中"全部"；默认落地为 Skills + 全部。
- "全部"视图聚合同类全部资产，按来源分段：全局适用段在前，各项目段按名称排序在后；段内沿用既有筛选／稳定排序／分页契约。
- 具体项目视图保持现状的"项目自有 + 全局适用"两段（A 布局）；全局视图仍只含全局资产。
- 第一栏收窄（约 180px），让出的宽度给主表面。
- 窄屏单表面栈顺序相应调整为 类型 → 作用域 → 列表 → 详情，层数不变。
- UI-B2-01（上下文优先候选）处置为"拒绝"：Mock 回归基线 4.3，无需为导航顺序回写正式产物。
- 不变：全局搜索、Agent 固定分列、master-detail、review/confirm/apply、dirty guard、A/B/C 布局决策（inherit 参数仍只作用于项目视图）。

## Capabilities

### New Capabilities

- `type-first-navigation`: 类型优先两栏导航、作用域选择器与默认"全部"、窄屏栈顺序。
- `cross-source-asset-grouping`: "全部"视图的跨来源分段聚合及其与排序/筛选/分页的关系。

### Modified Capabilities

（本仓库 openspec/specs 暂无既有能力；b2-state-scannability 尚未归档，其 `source-distinction` 的分段语义在本 change 中被复用并扩展到"全部"视图，归档时按时间顺序叠加即可。）

## Impact

- 主要影响面：selected Mock 的导航骨架、列表数据装配（跨上下文聚合）、面包屑、窄屏栈、全局搜索目的地提交。
- 测试影响面较大：现有 L1/L2 大量用例编码了"先选上下文再选类型"的路径，需要系统性改为类型优先路径（属对齐设计意图，不是放宽）。
- 正式产物：方向与基线 4.3/5.2/7.4 一致，定稿后基线无需为导航顺序改动；只需复核"项目上下文可见全局适用资产"的 Mock 假设与基线筛选/分组语义的关系。UI_CHANGE_IMPACT.md 需登记 UI-B2-01 的拒绝与本增补。
- 不改变：资产身份、作用域与授权模型；任何写入路径；无新增依赖/IPC/DTO。
