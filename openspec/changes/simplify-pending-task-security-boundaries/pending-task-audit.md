### 记号

- **Formal**：`A/U` = active change 中 unchecked；`R/Vp` = ticket `ready-for-agent` 而 verification 为 planned/unverified；`B` = ticket/gate blocked；`D` = upstream done。`prev` 表示任务序列中的必要前序项，不能据此覆盖 ticket 的 direct blocker。
- **TM**：`Prod` = 一般产品功能；`Path` = 外部项目路径/symlink；`Secret` = grant/敏感明文/revision/stale；`Write` = transaction/apply/recovery/权限/跨资产；`Adapter` = 不受信任 Adapter/config/extension/executable；`TR` = trusted-runner 验证基础设施；`Prov` = provenance/历史证据。
- **Class / disposition**：`F` = 产品功能，`PS` = 产品安全，`VI` = 验证基础设施，`TH` = 理论 hardening，`Q` = 独立质量审查，`RG` = release governance；`K` = 保留，`S` = 简化，`H` = 后置，`I` = 单独立项。没有既有 task 在本轮建议删除；任何删除需独立用户决定。
- **Validation**：只列未来最小层级。`FC` = functional complete 的必要检查；`HC` = hardening pending；`—` = 不产生产品测试 credit。L3 只在真实产品边界仍需要时保留，并且隔离/合成输入不得冒充真实用户项目或生产 artifact。
- **V/R/S**：未来 verifier / registry / schema-or-wire 影响。`0` = 无；`future` = 仅作为后续获批 apply 的影响，当前不能声称命令或状态机已存在。

## 汇总 disposition 与目标顺序

1. **保留为产品功能或产品安全**：B2 的 FE-03 draft/grant、FE-04 transaction/recovery、FE-05 create/import、FE-06 conversion safety、FE-07 external project/index、FE-08 untrusted Adapter、FE-09 delete/recover，以及对应的必要 L0/L1/L2 和真实产品边界 L3。
2. **简化为公共验证基础设施**：重复 preflight、registry/manifest/verifier route、wire drift helper、代表性 identity negative tests 与 provenance projection。公共能力只能降低重复实现，不能混合 ticket identity 或 closure credit。
3. **拆解 acceptance/verifier 循环风险**：审计发现计划文本可能把 ticket acceptance、formal contract、verifier capability 与 closure 互设前置；当前未观察到 runtime cycle，且 registry 仅含已完成的 FE-02、FE-01、FE-07R。future apply 必须按 formal acceptance 冻结 → 最小 verifier capability → ticket 自身 evidence 与 formal closure 的单向顺序，verifier 不得扩大 acceptance，closure 也不阻塞 verifier 建立。
4. **统一后置**：PF、performance、stress、platform hardening、低概率 trusted-runner 对抗验证，以及需要它们的 formal comparison；后置未运行只记 `hardening pending`，绝不记通过。
5. **单独立项**：同权限恶意目录交换、native evidence-only `openat` helper、跨平台安全文件系统、复杂 binary provenance，或任何扩大到 compromised runner/toolchain 的要求。
6. **未删除历史**：FE-02 的历史 PF failure/waiver、所有现有 evidence、完成 task 和 frozen acceptance 保持不变。改变 frozen acceptance、release gate 或真实产品安全边界必须回主任务取得用户显式决定。
