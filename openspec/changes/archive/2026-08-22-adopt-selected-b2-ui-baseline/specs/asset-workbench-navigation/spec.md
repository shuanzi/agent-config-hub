## Purpose

定义 MVP 资产工作台的类型优先信息架构，使用户在保留来源可见性的同时，以一致的作用域、列表、搜索和窄屏旅程定位三类可管理资产。

## ADDED Requirements

### Requirement: MVP 可见资产类型

系统 MUST 将资产工作台的一级导航、全局搜索和创建入口限制为 Skills、长期指令与 Subagents 三类 MVP 可见资产，并且 MUST NOT 为兼容性资产生成或解析任何 MVP 工作台目的地。

#### Scenario: 遗留 Hook 资产存在

- **WHEN** 系统读取到可用于兼容性或遗留证据的 Hook 资产
- **THEN** Hook MUST NOT 出现在 MVP 的一级导航、全局搜索结果或创建入口中

#### Scenario: 遗留选择或引用指向 Hook

- **WHEN** 历史选择、缓存状态或直接引用请求将一个 Hook 解析为工作台目的地
- **THEN** 系统 MUST 返回无可用 MVP 目的地且 MUST NOT 渲染 Hook 详情

### Requirement: 类型优先的作用域选择

系统 MUST 先让用户选择资产类型，再独立选择全部、全局配置或一个具体项目的作用域；默认选择 MUST 为 Skills 与全部作用域。

#### Scenario: 用户进入工作台

- **WHEN** 用户首次进入资产工作台
- **THEN** 系统 MUST 显示 Skills 的全部作用域列表，并提供三种资产类型和三类作用域的可达选择

#### Scenario: 用户选择具体项目作用域

- **WHEN** 用户在任一已选资产类型下选择一个具体项目
- **THEN** 系统 MUST 以该项目为当前作用域读取列表，而不得把项目标签或路径当作项目身份

### Requirement: 来源分段与单一全局分页

系统 MUST 在每个视图上下文中依次完成筛选、固定来源分段顺序、段内稳定排序、结果扁平化和单一全局分页。`all` MUST 先显示非空全局适用段，再显示非空项目段；项目段 MUST 按项目展示名稳定升序，展示名相同时 MUST 以不透明 `projectId` 作确定性 tie-break。`global` MUST 只显示非空全局资产段。`project` MUST 先显示非空项目自有段，再显示已解析的非空全局适用段。空段 MUST NOT 渲染。系统 MUST 保留来源分段可见性、聚合总数和跨段边界语义，而不得为各分段建立独立分页。

#### Scenario: 页面跨越来源分段边界

- **WHEN** 一个分页页尾包含某来源分段的最后资产且页内继续包含下一来源分段的资产
- **THEN** 系统 MUST 在同一全局分页中保留两个来源分段、跨段边界和聚合总数，而不得为各分段创建独立分页

#### Scenario: All 视图包含同名项目段

- **WHEN** All 视图包含多个非空项目段，且其中多个项目展示名相同
- **THEN** 系统 MUST 在非空全局适用段之后按项目展示名稳定升序显示项目段，并以不透明 `projectId` 确定同名项目段的顺序

#### Scenario: Global 与 Project 视图呈现段序

- **WHEN** 用户分别读取 Global 视图和具体 Project 视图
- **THEN** Global 视图 MUST 只渲染非空全局资产段，Project 视图 MUST 先渲染非空项目自有段再渲染已解析的非空全局适用段，且两种视图都 MUST NOT 渲染空段

### Requirement: 仅作定位的全局搜索

系统 MUST 将全局搜索作为资产定位功能，搜索结果只包含 MVP 可见资产类型，且搜索本身 MUST NOT 授权或触发写入。

#### Scenario: 用户从搜索结果定位资产

- **WHEN** 用户选择一个全局搜索结果
- **THEN** 系统 MUST 导航到该资产的可查看上下文，并且 MUST NOT 因该搜索操作创建草稿、准备写入或改变实际资产状态

### Requirement: 窄屏工作台旅程

系统 MUST 在窄屏中按资产类型、作用域、列表、详情或编辑的单表面栈组织工作台，并在返回或前进时保留已选择的上层上下文。

#### Scenario: 窄屏用户打开资产详情

- **WHEN** 用户已选择资产类型和作用域并从列表打开一个资产
- **THEN** 系统 MUST 在详情或编辑表面展示该资产，并保留返回同一类型、作用域和列表上下文的路径
