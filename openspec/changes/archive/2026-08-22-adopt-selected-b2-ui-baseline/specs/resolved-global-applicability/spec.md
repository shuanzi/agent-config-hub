## Purpose

定义项目视图如何以版本化适用性事实投影全局资产，确保用户能审计来源和覆盖关系，同时让未知或受阻的适用性安全地保持封闭失败。

## ADDED Requirements

### Requirement: 具体项目的已解析全局投影

系统 MUST 将全部、全局配置和具体项目视图区分为独立的读取上下文。具体项目视图 MUST 包含其项目自有资产，并且仅在版本化适用性解析明确确认全局资产对该具体项目生效时，才将该全局资产列入全局适用分段。

#### Scenario: 全局资产已确认对项目生效

- **WHEN** 一个全局资产具有针对当前具体项目的已解析生效上下文
- **THEN** 系统 MUST 在该项目视图的全局适用分段中显示该资产及其已解析事实

#### Scenario: 项目没有已确认适用上下文

- **WHEN** 一个全局资产没有针对当前具体项目的已解析生效上下文
- **THEN** 系统 MUST NOT 将该资产列入该项目视图的全局适用分段

### Requirement: 不透明身份和可解释的适用事实

系统 MUST 使用不透明的具体项目身份判定适用性，不得用项目展示名称或路径代替身份；每个已解析生效上下文 MUST 提供 Adapter 身份和版本、规则版本、权威读取修订、具体上下文身份、来源层级、加载顺序、优先级和覆盖关系等可解释事实。

#### Scenario: 两个项目具有相同展示名称

- **WHEN** 系统解析两个展示名称相同但身份不同的项目
- **THEN** 系统 MUST 依据各自不透明身份分别呈现适用性事实，而不得因展示名称相同合并其投影

### Requirement: 未知或受阻适用性的封闭失败

系统 MUST 将未知或受阻的项目适用性表示为可检查的可用性或发现事实，并提供稳定原因代码；此类资产 MUST NOT 进入任何项目的全局适用分段。

#### Scenario: 适用性解析被阻断

- **WHEN** 系统无法确认一个全局资产对当前项目是否生效
- **THEN** 系统 MUST 在全部或全局配置作用域中使该阻断事实可检查，并以稳定原因解释，同时不得把该资产投影为项目全局适用资产

### Requirement: 适用性 freshness 与写入前重验

系统 MUST 将每个项目适用性投影绑定到产生它的 Adapter／规则版本和权威读取修订。版本或修订已过期的投影 MUST 被视为未知或受阻，且 MUST NOT 继续进入项目的全局适用分段。系统 MUST 在 prepare 前及 apply 前重新读取相关事实并重验适用性；如果版本、修订或受影响上下文集合发生变化，系统 MUST 使旧审查结果失效并要求重新计算和审查，而不得依赖过期投影写入。

#### Scenario: 已解析适用性变为过期

- **WHEN** 当前 Adapter／规则版本或权威读取修订不再匹配一个已缓存的项目适用性投影
- **THEN** 系统 MUST 以稳定原因将该投影标记为未知或受阻，并且 MUST NOT 继续把该全局资产列入项目的全局适用分段

#### Scenario: 写入前受影响上下文发生变化

- **WHEN** prepare 前或 apply 前的权威重读发现项目适用性版本、修订或受影响上下文集合已变化
- **THEN** 系统 MUST 阻止沿用旧审查结果，并要求基于新事实重新计算、审查和确认后才允许写入

### Requirement: 项目上下文中的全局资产保持原生归属

系统 MUST 在项目视图中保持被投影全局资产的全局 `AssetRef` 和全局作用域；任何编辑 MUST 写回该全局原生资产，并在审查或确认前展示所有已解析的受影响上下文。系统 MUST NOT 因项目视图操作创建项目资产副本。

#### Scenario: 用户从项目视图编辑全局资产

- **WHEN** 用户从项目视图对一个已投影的全局资产发起编辑
- **THEN** 系统 MUST 保持该资产的全局 `AssetRef` 和作用域、写回全局原生资产，并在确认写入前显示其所有已解析的受影响上下文，而不得隐式创建项目副本
