# Design: b2-type-first-nav

## Context

动机见 proposal.md。关键事实：正式基线 4.3 本就是类型优先，当前 Mock 的上下文优先是未批候选（UI-B2-01，pending）。已实现可复用的前置件：A 布局分段同表（b2-state-scannability 强化了分段层级与 badge 专色）、Agent 固定分列、内容型 master-detail、20/50/100 分页与稳定排序契约（CR-UI-B2-001）。规模预期几十项资产、3 个受管项目。

## Goals / Non-Goals

**Goals:**

- 类型成为一级持久选择；作用域成为第二级收窄；默认"全部"聚合。
- 跨来源分段复用 A 布局语言，不新增视觉体系。
- 全部既有安全语义（guard、焦点、闭环）原样保留。

**Non-Goals:**

- 不引入"Agent"作为导航维度（基线明确不建 Agent × 项目工作台）。
- 不做跨来源批量操作；聚合视图仍是逐资产管理。
- 不动 inherit=B/C 的开发对照（仅项目视图可达）；"全部"视图只用 A 式分段。
- 不改全局搜索的索引与结果结构，只调整目的地的上下文提交。

## Decisions

### D1: 第二栏是纯选择器，不承载管理入口

"纳入项目"等管理动作留在顶栏。第二栏混合"选择作用域"与"管理项目"会模糊导航心智；基线也把项目管理定位为独立管理入口。

### D2: "全部"的段序：全局在前，项目按名称

全局资产适用于所有项目，是各项目段的"公共前缀"，放最前符合阅读顺序（先通用后特异），也与项目视图"项目自有 → 全局适用"形成镜像但不冲突——两种视图的段序各自服务于该视图的主语。备选：项目在前——拒绝，"全部"视图的主语是类型而非某项目。

### D3: 作用域切换保留类型与列表控制状态

切作用域时类型、筛选、排序、每页数量保留（沿用 CR-UI-B2-001 的"变化回第 1 页"）；这让"全部 → 某项目"的收窄动作零成本可逆。

### D4: 第一栏收窄至约 180px，三档断点同步

类型只有 3 项短标签，252px 是纯浪费；收窄后主表面获益直接。1200–1360 与窄屏的对应收窄同步调整，列宽验收线沿用"路径折行不超过两行、Agent 列不溢出"。

### D5: 状态装配改动最小化

`configContext` 增加 `全部` 取值（或等价表示），列表装配层在"全部"时聚合所有项目 + 全局 seed 并按来源分段；资产身份仍携带原始上下文，详情/编辑/事务流程继续按资产自身上下文运行——聚合只是列表读模型，不产生新的资产语义。面包屑在"全部"时显示 `全部 › <类型>`。

## Risks / Trade-offs

- 写操作的作用域显著性下降（导航第一层不再是上下文） → 详情头部状态条与 review/confirm 页的 target identity 已承载作用域；本轮额外要求编辑区头部的作用域标识保持常显，验收时专项核对。
- "全部"视图行数膨胀（类型 × 全部来源） → 几十项规模下单类型全量约 20–40 行，一页 20/50/100 可承载；若未来项目数大增再评估虚拟化，本轮不做。
- L1/L2 大量用例编码上下文优先路径 → 任务组专列系统性改造；属于对齐设计意图的改写，逐条核对不放宽断言语义。
- 同名资产在聚合视图并存可能引发"为什么有两个 AGENTS.md"的初次困惑 → 分段标题 + badge 双重表达；备选（合并显示）被 spec 明确拒绝。

## Open Questions

- "全部"视图下内容型 master-detail 的左列表是否需要来源徽标之外的更多上下文（如项目段内再按项目分子标题）——按当前分段方案已可辨识，实施时用真实密度数据复核。
