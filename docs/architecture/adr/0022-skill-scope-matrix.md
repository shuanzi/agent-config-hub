# ADR-0022：目标绑定资产上的 Skills 使用矩阵

状态：Accepted；2026-10-14 用户确认矩阵与直接勾选交互。实现和验证情况另见[矩阵验收记录](../../acceptance/skill-matrix-results.md)，此批准不等于各 Agent 的运行时验收。

适用性：Codex／OpenCode 未接入的历史限制由 [ADR-0023](0023-project-skill-exclusion-launch.md) 扩展；下述为矩阵初始决策，当前能力以产品说明为准。

## 背景

数量较多的 Skills 需要按全局／项目和 Agent 组合管理。旧目录图标只控制投放，项目页操作全局行会改全局资产，不能表达「仅此项目排除」。共享扫描目录也使四个 Agent 的可用性不能独立推断。

## 决定

在既有 `InstalledSkill + ScopeTarget` 上增加矩阵读、分配预览和应用三个直接命令，保留 ADR-0020 的 services 分层，不引入通用事务系统、新数据库实体或按名称合并的主资产库。

矩阵的来源目标与分配目标分开传递。全局来源在项目中取消勾选只写该项目的原生配置；不会撤回全局文件。向另一个目标新增投放时复制独立主资产，复用既有来源身份及版本信息；不共享可变主副本。相同 ID 的不同来源／内容拒绝覆盖，即使显示名相同也不视为同一版本。

目录状态仍由 placement 所有权、签名、物理路径及别名判断。矩阵对共享目录的读取关系作显式呈现，保留目录维护入口。只实现已核对的 Claude Code `skillOverrides` 和 Gemini CLI `skills.disabled` 配置写入；Gemini 上级停用不能通过下级启用解除。Codex／OpenCode 从其他目录发现内容时，其局部停用能力未完成接入，显示限制并拒绝不成立的独立停用。

勾选进入前端草稿。预览保留原 revision，不静默接受外部变化；应用逐项再核对，成功项清除、失败项保留。多项之间不承诺原子提交，已有单项投放检查点继续适用。草稿保存在当前 App 生命周期内，不新增后台状态或跨进程草稿恢复。

## 取舍

保留目标绑定资产、既有更新与备份身份，避免本次改变历史副本的内容所有权。原生 JSON 保留其他字段，拒绝无效结构与配置文件／目录链接；不管理原生插件、企业策略、额外 CLI 参数、子目录工作区、OpenCode 每 Agent 权限或 Agent 会话是否加载。未来扩展原生能力需独立验证其路径、合并、冲突和运行时规则。
