# 产品说明

本文是当前产品行为的权威说明。基础基线：2026-09-27，polished 实现提交 `cd175f4` 及验收交付 `4448ffc`；2026-10-14 的 Skills 矩阵增量见[验收记录](../acceptance/skill-matrix-results.md)。这些是实现与本地证据，不是正式发布状态。技术细节见[架构说明](../architecture/README.md)，交互与请求契约见[前端说明](../frontend/README.md)，操作步骤见[验收指南](../acceptance/polished-ui.md)。

## 范围与术语

面向本地单用户，管理 Skills、长期指令 AGENTS.md、原生 Subagents，并提供全局设置。四种 Agent 为 Claude Code、Codex、Gemini CLI、OpenCode。当前不提供 Hooks、跨 Agent 格式转换、动态 Adapter、全局搜索、通用 prepare/review/confirm/apply 事务流程或自动后台更新。

| 术语 | 含义 |
| --- | --- |
| 配置上下文 | 列表读取范围：全部、全局、一个已登记项目 |
| 完整目标 | 资产的全局归属，或携带稳定 `projectId` 的项目归属；“全部”不是写入目标 |
| 主资产（SSOT） | 受管 Skill 的内容副本；独立于目录投放位置 |
| 投放位置 | Skill 可出现的目录；`shared` 是共享目录，不是第五种 Agent |
| 目录别名 | 多个逻辑位置解析到同一物理目录，显示时合并，不能独立写入／撤回 |
| 未接管 | 已存在的本地内容，尚未授权应用按受管记录修改 |
| 原生定义 | 属于一个 Agent 的 Subagent 文件或配置条目，不进行跨 Agent 转换 |

文件存在、已投放、已启用均表示文件配置状态，不证明 Agent 已加载、遵循或执行成功。

## 配置上下文与项目

默认进入 Skills 的“已安装／全部”，以使用矩阵管理。“全部”聚合全局及已登记项目。具体项目中的 Skills 显示项目自有条目及至少有一处实际投放的全局条目；AGENTS.md 显示项目与全局文档；原生 Subagents 只扫描该项目目标。显示在项目页的全局项仍保持全局归属，不因查看或操作而复制到项目；这不是对 Agent 运行时继承／加载的推断。

登记项目使用系统目录选择器。根目录须存在且可访问，规范化后的同一路径不能重复登记；同名项目允许存在，以路径展示消歧，以数据库生成的 `projectId` 保持身份。全部上下文的项目顺序由 registry 的显示名及 ID 确定。

已有资产的操作始终使用资产自身目标。安装、ZIP 导入等新操作在“全部”中必须先明确选择全局或项目；页面顶部目标不会改写已有行的归属。发现数据可来自同一仓库，但已安装状态按完整目标计算。

项目根不可用时，针对该项目的读写返回错误，不能回退到全局。全部上下文读取可跳过不可访问项目；因此聚合结果不等于所有磁盘内容均已扫描。

重新关联项目根保留 `projectId`，拒绝重复根路径；仍有已登记 Skill 投放时必须先撤回。存在原生 Subagent 管理记录或备份时阻止改绑。移除项目仅解除登记，不删除项目文件；受管资产或相关备份会阻止移除。项目根不可用时仍可删除存储在应用目录中的项目 Skill 备份，再按条件解除登记；应用不自动删除这些备份。

## Skills

### 来源与安装

支持 GitHub 仓库管理、按需发现、ZIP 安装及本地未接管目录导入。仓库记录包含 owner、name、branch、enabled；可添加、查看和移除，默认集合含 `anthropics/skills`。非法坐标被拒绝；发现下载有大小、解压条目与路径安全限制。发现以含 `SKILL.md` 的目录为 Skill，名称和描述来自 frontmatter，缺失时按实现回退。

发现安装和 ZIP 安装必须显式选择 `initialLocation`，只初始化该位置。取消系统文件选择、未选择位置或目标无效都不安装。同一目标内同源重复安装可复用受管记录并投放至所选位置；同名不同源占位返回冲突。同名 Skill 可分别属于全局及多个项目，各自独立。

### 目录投放与接管

全局展示四种 Agent 目录及共享目录；项目按实际支持路径展示，不增加独立 `shared` 入口。详情展示全部实际路径、别名、状态、不可操作原因与主资产位置。路径表见[架构说明](../architecture/README.md#目录与身份)。

| 状态 | 可执行动作 |
| --- | --- |
| 已投放 | 在可撤回时移除本位置的受管投放，保留主资产及其他位置 |
| 未投放 | 按同步方式投放到此位置 |
| 已存在、未接管 | 进入来源选择和接管预览，不能直接覆盖 |
| 冲突 | 显示原因，拒绝无效写入，外部内容保留 |

`auto` 优先符号链接、失败时回退复制；也可选 `symlink` 或 `copy`。位置与主资产为同一目录时不能独立撤回。关闭 Codex 专用目录不表示 Codex 无法从共享目录发现该 Skill。

导入须选择唯一来源及要管理的位置，先预览来源原件、受管位置与逐路径动作，再确认。未选择的位置不自动取得所有权。执行投放和导入时复验 revision；预览之后的外部修改会使操作失败，需重新读取和预览。

旧版已安装 Skill 若缺少投放归属登记，先通过“导入已有”选择主副本或同内容来源，预览并确认登记。保留原身份、目标、来源和安装时间，只接管显式选中的位置；不会在启动时按旧 `apps` 标记自动认领目录。已有受管记录的外部修改、残缺归属或其他资产占用仍拒绝重新登记。

### 使用矩阵与批量分配

矩阵按 Skill 来源与完整目标区分行，四列对应 Agent。名称、描述、来源搜索以及 Agent／状态筛选支持大量条目；全选作用于全部筛选结果，显示数量。项目矩阵包含此项目资产及全部全局受管来源，因此未投放的全局收藏也可指定给项目。不同目标的同身份、同版本副本在项目矩阵中优先展示项目副本；不同内容或来源不会自动合并或覆盖。

勾选／取消勾选暂存草稿，预览并应用才写入。切换项目保留已带完整目标的草稿；窄屏返回和切换资产页同样保留；刷新页面不保证保留。批量选择 Skills、全局／多个项目和 Agent，先读取各目标状态，跳过无需变更的项，预览列出受限制项。应用逐项复验，成功项清除，失败或受限制项保留；不承诺批量原子提交。预览不自动采用变化后的 revision。

跨目标新增目录投放时复制独立主资产并登记投放，保留来源、版本和目标身份；不改变来源目标，也不使已存在副本随来源更新。向已有同身份不同版本或其他内容占位的目标写入会失败，需在目录与维护中核对。

状态包括已投放、来自全局、本范围已启用、本范围已排除、未使用、未能读取。共享目录、项目 `.agents/skills` 以及 OpenCode 对 Claude 目录的读取关系会影响其他列；不能把四列理解成彼此独立的目录开关。原有路径和目录覆盖规则继续适用，此状态不证明 Agent 会话已加载。

来自全局的取消勾选仅修改当前项目的原生停用配置，不删除全局投放或改写其他项目。Claude Code 使用 `.claude/settings.local.json` 的 `skillOverrides`；Gemini CLI 使用 `.gemini/settings.json` 的 `skills.disabled`。Claude Code 重新勾选移除本范围排除；上级用户配置停用时写入项目 `on`，只在此项目单独启用。Gemini CLI 重新勾选移除本范围排除；上级仍停用、精细可见性、同名不同来源、插件内容、无效 JSON 或链接配置显示限制。原生写入保留其他 JSON 字段，写入前重新检查文件，失败不覆盖外部修改。

OpenCode 项目排除读取全局、项目根及 `.opencode` 中的 JSON／JSONC，按加载顺序选择最后存在的项目配置；没有文件时创建项目根 `opencode.json`。旧格式写入 `permission.skill` 的精确名称 `deny`，写入前持久保存原精确值；重新勾选恢复原 `ask`／`allow`，原无值时只移除管理器新增的项。没有原权限记录的原生或旧版 `deny` 保持不变，须在原生配置中核对。任一已加载配置中的相关权限被外部修改时拒绝恢复旧值，刷新状态也不会跳过该保护；无关字段与其他 Skill 的修改继续保留。新格式追加 `permissions` 的精确 Skill 规则，重新勾选移除对应项目排除并重新计算继承状态；上级或通配规则仍停用时显示限制，不自动放宽权限。原生 `ask` 保留，显示加载需要确认的说明。编辑保留注释、未知字段和规则顺序；新旧格式混用、角色覆盖、无法识别的策略以及会使精确停用失效的后置通配顺序均拒绝操作。

Codex 项目排除保存到 `.codex/acm-skills.json`，结构为 `version: 1` 与 `excludedSkillIds`；重新勾选移除该身份。项目矩阵中的 Codex 列及单元格明确标注「启动入口生效」。项目工具栏的「启动 Codex」读取已保存规则、完整项目路径与当前受管扫描路径；存在本项目未应用草稿时需先应用或撤销。入口使用已配置的 Codex 全局目录，在 macOS Terminal 启动新 CLI 会话，通过 `-c skills.config=…` 附加每个真实 `SKILL.md` 路径的禁用参数，保留用户规则。CLI 缺失、项目不可访问、无效策略或启动计划变化时显示错误；成功反馈仅表示已交给终端。已卸载的身份保留排除记录并提示暂不适用，重新安装同身份后继续排除。

本机 Codex 0.162.1 的 Skill 开关只接受用户配置及会话参数，项目 `config.toml` 中的开关不会生效。普通 CLI、桌面、IDE 及已运行会话继续使用原生配置；项目启动入口控制由它启动的新 CLI 会话。用户配置已停用的 Skill 须在对应全局配置解除，不自动追加启用覆盖。

这两种排除只写当前项目规则，保留全局与项目 Skill 文件、其他 Agent 和其他项目的配置。全局矩阵继续遵循原有目录撤回限制，未扩大全局原生开关。完整路径、接管、更新、卸载和备份继续使用「目录与维护」。插件、企业策略、额外会话参数、外部配置来源及所有原生角色权限的完整模拟仍不属于矩阵能力。

### 更新、卸载与恢复

更新检查由用户触发，比较仓库内容与本地 hash，不后台轮询。更新前备份，更新及重投放保持原目标，并检查受管目录是否被外部修改。网络失败显示可重试错误，不伪装成空结果。

卸载带确认，先保存备份，再按受管关系撤回投放并清除主资产与记录；冲突不能静默覆盖。备份支持查看、恢复及删除，保存原目标，不能跨全局／项目恢复；项目恢复要求根可用。旧 Skill 备份缺少 `locations` 时按备份内的 `apps` 恢复原 Agent 位置；新格式明确的空位置列表仍表示不恢复投放，恢复时同样保留目标与冲突保护。Skill 备份保留最近 20 份，备份目录不随主资产迁移。该数量限制不应套用到原生 Subagent 备份。

## AGENTS.md

每个完整目标只有一个逻辑 `AGENTS.md`；文件不存在时仍显示可编辑的未创建条目。全局默认对应 Codex 与 OpenCode 的两个文件，项目仅对应项目根的一个文件。页面展示实际 `paths[]`，不显示“对某 Agent 生效”的承诺。

保存全局文档将同一内容写入两个有效路径。两份既有内容不一致时，读取或保存返回冲突，不自动选一份覆盖另一份；写入过程失败会尝试恢复已经写入的文件，并报告失败。项目保存不影响全局文件。

不管理 `CLAUDE.md`、`GEMINI.md`，也不自动导入、改名或迁移它们。没有指令预设库、物理删除、导入或按 Agent 启停入口；既有旧数据不自动转换为新文档。

## 原生 Subagents

只读发现本地原生定义后，由用户显式接管；每条定义属于单个 Agent、完整目标及明确来源，不按显示名跨来源合并。支持 Claude Code Markdown、Codex TOML、Gemini CLI Markdown、OpenCode Markdown 或原生配置条目；项目 Codex TOML 已支持。

接管后可编辑原生源码、启停、备份、恢复、卸载。保存和覆盖动作校验读取时的内容摘要；外部修改、占位冲突或失效来源使操作中止。文件型停用移出 Agent 扫描目录，配置型操作只处理对应条目，保留其他配置和未知字段。

文件本身是符号链接时需额外确认，以独立副本接管，外部目标不变；配置范围内部祖先目录为链接时只读展示并拒绝写入。无效定义显示诊断，Gemini 功能开关仅诊断，不自动开启。

仓库发现与安装按单个兼容 Agent 和完整目标执行；更新先展示本地与远端差异，应用时同时校验本地和远端摘要。备份绑定原定义和目标；覆盖恢复需要目标摘要，删除备份需确认。旧模型记录及备份保留为待核对材料，不自动转换、重投放或删除。详细决策见 [ADR-0021](../architecture/adr/0021-native-subagent-management.md)。

## 设置

同步方式即时保存，供后续 Skill 投放使用；切换同步方式不应丢失尚未保存的目录覆盖草稿。目录覆盖须显式保存，通过专用命令处理受管路径及冲突。即使没有已投放 Skill，也须先创建或校验覆盖根下的 `skills` 目录；根或子路径被普通文件占用时拒绝保存，保留原设置及占位文件。界面一次保存多个 Agent 时按单个 Agent 命令执行，不承诺跨四项原子提交。

存储位置切换须迁移确认，在 hub 与 unified 之间移动 Skill 主资产及项目副本并重建受管投放。原生 Subagent 不因该选项转换为目录投影。迁移检查项目与目录冲突，失败尝试恢复设置、文件及登记状态；回滚异常也须报告，不能宣称成功。

Codex／OpenCode 目录覆盖可搬迁各自的全局 AGENTS.md 路径，另一份保持不变；目标存在不同内容时拒绝覆盖。Claude／Gemini 覆盖不搬迁长期指令。覆盖命令不搬迁原生 Subagent 文件；改变扫描目录后应重新读取并核对原定义状态，不能把项目改绑保护推定为全局目录覆盖也有相同限制。

## 能力与证据边界

浏览器验收使用正式 App 和模拟命令，只证明相应界面交互。桌面验收使用隔离目录与真实命令，文件读回及新进程回读才作为持久化证据。在线发现、安装和更新独立报告；已有同源更新验证不等于跨版本升级验证。

正式签名、公证、发布、性能预算均未取得当前实现的完成证据。旧 Demo 中的全局搜索、分页、转换、事务流程与其他候选布局不构成正式产品能力。
