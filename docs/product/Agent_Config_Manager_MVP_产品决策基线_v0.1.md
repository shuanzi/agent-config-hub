# Agent Config Manager：MVP 产品决策基线 v0.1

> 状态：MVP 产品范围已封板；UI/交互与视觉规范已收口
> 更新时间：2026-07-26
> 适用阶段：UI/交互设计基线（已确认）
> 文档性质：产品决策基线，不是详细技术设计或实施计划

## 1. 文档目的

本文档固化现阶段已经确认的产品决策，作为后续产品设计、技术方案、任务拆分与验收的共同基线。

本文按产品主题重组结论，不复刻逐轮问答顺序。MVP 产品范围现已封板；后续 UI/交互设计、技术方案和任务拆分均以本文为边界，不在未显式重启产品范围决策的情况下继续增加 MVP 能力。

UI/交互待确认项采用“推荐默认值先行、按主题集中验收”的收敛方式：

- 每项仍提供明确的 A/B/C 视觉方案、价值、代价、适用条件和客观推荐；
- 不再逐项等待确认；若用户未提前指定偏好，则以客观推荐作为待验收默认值继续推进相邻问题；
- 待验收默认值不等同于已确认产品决策，在集中验收前不得写入“已确认决策索引”或表述为已封板结论；
- 相邻问题按主题成批组织，每批默认不超过 5 项；主题边界提前结束时可提前进入验收；
- 集中验收时一次列出全部默认值及关键代价，用户可以整批接受，也可以只修改例外项；
- 只有完成集中验收后，才把对应默认值转为已确认结论并更新本文相应主题与决策索引。
- UI/交互收尾阶段只把会改变核心闭环、安全判断或高频效率的流程级问题提升为独立 A/B/C 决策；
- 微观文案、图标、间距、局部动效、标准状态，以及可由已确认模式直接推导的次要交互不再逐项确认，统一转入视觉规范与原型验收；
- 最后一批核心问题完成集中验收后，除非原型暴露新的产品级权衡，不再继续枚举 UI 微决策。

截至 2026-07-26，UI/交互产品级决策与统一视觉规范均已完成集中验收；当前没有待确认的 UI/视觉问题。

## 2. 一句话定义

Agent Config Manager 是一个面向单用户、本地运行、跨 Coding Agent 的配置资产控制台。

它统一发现、理解和安全管理以下四类原生资产：

- Skills
- 长期指令文件，例如 `CLAUDE.md`、`AGENTS.md`、`GEMINI.md`
- Subagents
- Hooks

首版一等支持：

- Claude Code
- Codex
- Gemini CLI
- OpenCode

产品的核心价值不是收藏配置文件，也不是运行 Agent，而是让用户能够：

> 按资产类型看清本机上有哪些 Agent 配置、它们在哪些上下文中生效，并以可验证、可预览、可恢复的方式完成管理和跨 Agent 转换。

## 3. 产品定位与边界

### 3.1 已确认定位

MVP 定位为：

> 单用户、本地、跨 Agent 的配置控制台。

主要职责包括：

- 发现四类配置资产；
- 解析其原生结构、路径、作用域和生效上下文；
- 支持创建、导入、编辑、转换、安装、原生资产导出及后续恢复；
- 识别来源、覆盖、冲突、漂移和兼容性状态；
- 在写入前提供确定性校验和差异预览；
- 在能力或版本边界不明确时封闭失败。

### 3.2 MVP 不做

MVP 不承担以下职责：

- Agent 对话、任务执行或多 Agent 编排；
- Agent 本体的安装、升级、卸载或运行时托管；
- 云同步与团队协作；
- 在线市场、社区模板库或远程分发平台；
- 完整 IDE 或通用文件管理器；
- 跨资产依赖图、入向引用扫描、断裂影响分析或级联修改；
- 用户可扩展的第三方 Agent 适配器 SDK 或插件机制；
- 产品自有的跨 Agent 统一配置 DSL；
- Agent 凭证的创建、轮换、同步或注入；
- Hook、Skill 脚本或插件代码的执行与沙箱运行；
- 跨 Agent 行为等价性的自动证明。
- 诊断包、问题报告包或完整环境备份与迁移。

产品架构可以为未来扩展保留边界，但上述能力不进入 MVP 的实现与验收范围。

## 4. 核心产品原则

### 4.1 原生资产优先

- 各 Agent 的原生文件、目录、配置块或插件模块是产品直接管理的对象。
- 产品统一的是发现、展示、校验、变更和恢复流程，不是资产格式。
- 不要求用户迁移到产品私有格式，也不使用产品私有格式替代原生资产。

### 4.2 原位管理

- 目标 Agent 的原生资产是唯一事实来源。
- 产品不建立一套中央资产副本库。
- 创建、导入、安装和转换的结果直接落到目标 Agent 的原生位置。
- 复制或转换完成后，目标资产成为独立原生资产，不与源资产保持自动同步。

### 4.3 资产类型优先、上下文感知

- 一级信息架构固定为 Skills、长期指令、Subagents、Hooks。
- 用户无需先选择 Agent 或项目，即可查看全部同类资产。
- Agent、项目、作用域和状态是筛选、分组与关系维度，不是与资产类型并列的主工作台。
- 不建设一套独立的“Agent × 项目”工作台。

### 4.4 默认封闭失败

- 只有被已验证解析器、规则、目标版本和能力矩阵明确覆盖的操作才允许写入。
- 对未知字段、未知结构、未知版本或无法安全映射的能力不做猜测。
- 明确降级或阻断优先于生成表面合法、实际不可用的结果。

### 4.5 无静默数据损失

- 不静默覆盖未知字段、注释、格式、外部修改或目标资产的手工变化。
- 任何可能造成不可逆变化的操作都必须经过预览、确认、快照和可恢复写入。

## 5. 资产模型

### 5.1 资产粒度

MVP 以各 Agent 的“原生可管理单元”定义资产边界：

| 资产类型 | 典型原生可管理单元 |
|---|---|
| Skills | Skill 目录包、`SKILL.md` 及其附属资源 |
| 长期指令 | 单个原生指令文件 |
| Subagents | 定义文件、配置项或原生配置块 |
| Hooks | 事件绑定、配置块、脚本或插件模块 |

产品不强迫四类资产都表现为单个物理文件，也不把它们转换为用户需要维护的统一记录。

### 5.2 资产身份

- 同一原生资产只保留一个产品实体。
- 同一资产可被多个 Agent、项目或作用域上下文发现，但不会因此产生副本。
- 资产身份至少关联原生位置、原生类型和适配器识别结果。
- 移动、复制或转换产生的新目标资产是独立实体。

### 5.3 生效上下文

每项资产都需要展示：

- 可被哪些 Agent 识别；
- 对哪些项目或全局环境生效；
- 所处路径及作用域；
- 来源层级和加载顺序；
- 是否被覆盖、合并、遮蔽或存在冲突；
- 修改后可能影响哪些上下文；
- 当前适配器和 Agent 版本是否允许安全写入。

产品应允许从资产进入上下文详情，查看完整解析链；但上下文详情不取代资产类型主视图。

## 6. Agent 支持范围

### 6.1 首版支持对象

Claude Code、Codex、Gemini CLI 和 OpenCode 均为一等支持对象，不设置“主要 Agent”与附属 Agent。

### 6.2 “支持”的验收含义

对一个 Agent 宣称支持，至少意味着其版本化适配器能够：

- 识别已验证版本及其配置结构；
- 发现该 Agent 已支持的四类原生资产及其作用域；
- 正确表达目标版本中“不支持某类能力”的事实；
- 解析原生可管理单元而不制造副本；
- 对已覆盖结构进行无损或明确有损的安全修改；
- 经过差异预览、校验、快照和事务式写入；
- 在未知或不兼容结构上降级为只读或阻断。

不要求所有 Agent 原生支持完全相同的四类能力，也不允许用虚构字段或模拟结构掩盖能力缺失。

### 6.3 首版扩展边界

- 不提供第三方 Agent 接入；
- 不提供自定义适配器 SDK；
- 不提供适配器插件市场；
- 后续增加 Agent 时仍需达到同一支持标准。

### 6.4 有界发现与显式纳入

- 自动识别已安装 Agent 及其标准用户级、全局级原生目录。
- 项目级资产仅在用户明确添加项目后纳入管理。
- 用户可以选择一个父目录进行一次性扫描；产品只展示候选项目，由用户确认具体纳入对象。
- 后台只监听用户已经确认的目录，不扫描整个用户主目录或磁盘。
- 使用规范化路径识别并去重同一项目。
- 不跟随符号链接越出用户已经授权的扫描或管理范围。
- 从产品中移除项目仅表示停止扫描、监听和管理，不删除、移动或修改任何原生资产。
- 项目路径消失或移动时标记为不可用，不自动重建目录或猜测新位置。

### 6.5 Agent 本体生命周期边界

- MVP 只以只读方式检测受支持 Agent 是否已安装、其已解析安装路径和版本。
- 产品不调用 `brew`、`npm` 或其他包管理器，不下载 Agent 安装包，也不修改系统运行时、`PATH` 或包管理器配置。
- 产品不执行 Agent 的安装、升级或卸载；检测到缺失、未知或不兼容版本时只展示状态，并按兼容性策略决定资产是否可写。
- Agent 检测与可能的后续生命周期管理能力保持模块边界分离；未来可以扩展，但不进入 MVP 的实现和验收范围。

## 7. 主要产品视图

### 7.1 主界面设计锚点

主界面优先服务“浏览、理解和编辑现有资产”这一最高频任务：

- 用户进入产品后首先能够看清已有资产、所在上下文和当前状态；
- 资产列表、筛选、详情与编辑构成主工作台；
- 跨 Agent 转换、删除、导出和恢复等能力作为资产操作进入，不占据产品中心；
- 状态总览用于辅助发现问题，不取代资产工作台成为默认首页。

该锚点只决定界面的任务优先级，不改变已经封板的 MVP 功能范围。

### 7.2 主工作区布局

主工作区采用“常驻双栏工作台”：

- 左侧常驻当前资产类型的资产列表，保留搜索、筛选、分组和当前选择上下文；
- 右侧常驻所选资产的详情与编辑区域，切换资产时在原位更新；
- 浏览、理解和编辑在同一工作区内连续完成，不以进入和返回独立详情页作为默认动线；
- Agent、项目、作用域和状态继续作为筛选或管理维度，不增加上下文导航栏；
- 不为同一资产分别设置快速检查器和独立编辑页两套主详情表面。

工作区各栏采用可拖拽分隔线调整宽度：

- 资产列表与右侧详情区之间提供可拖拽分隔线；
- 多文件资产中，固定文件树与当前文件内容之间提供可拖拽分隔线；
- 原生内容主区与固定辅助检查器之间提供可拖拽分隔线；
- 调整辅助栏宽度时，原生内容主区吸收剩余空间，并继续保持视觉与任务焦点；
- “固定常驻”表示对应面板在默认工作区中持续存在，不表示其宽度不可调整；
- 调整宽度只改变当前布局，不改变资产选择、当前文件、草稿或检查器上下文。

分隔线采用“细视觉线 + 宽命中区”：

- 常态仅显示 1 px 视觉线，降低对原生内容主区的视觉切割；
- 实际拖拽命中区域为以视觉线为中心的 8 px，命中区域不改变栏宽分配；
- 分隔线在悬停、获得焦点或拖拽时增强视觉反馈，常态继续保持克制；
- 可拖拽分隔线可以通过键盘获得焦点；
- `←` / `→` 每次调整 8 px，`Shift` + `←` / `→` 每次调整 32 px；
- `Home` / `End` 到达对应角色的可读下限或允许上限；
- 不使用 `Enter` 触发面板收拢，继续遵守手动调宽不触发自动收拢的既定规则。

栏宽拖拽采用“可读下限停止”：

- 每个可拖拽栏位按其角色设置能够保持内容可识别、关键操作可用的可读下限；
- 手动拖拽到该下限时，分隔线停止继续缩窄；
- 手动拖拽只调整栏宽，不触发面板自动收拢，也不允许形成仍占据栏位但内容不可读或操作不可用的极窄状态；
- 自动收拢仍只按已确认的窄窗口规则发生，聚焦仍需由用户显式进入；
- 各栏可读下限按下述“内容保护线”定义，最大宽度按随后“固定辅助栏上限”定义。

常规桌面工作区采用“内容保护线”作为各栏可读下限：

- 资产列表下限为 200 px，保证资产名称、关键异常及第二行 Agent、作用域等上下文仍可辨认；
- 多文件资产的固定文件树下限为 160 px，保证目录层级和当前文件仍可识别；
- 原生内容下限为 640 px，作为最大的保护线，优先保持源码阅读和编辑行宽；
- 辅助检查器下限为 216 px，保证常驻摘要与关键状态仍可识别；
- 上述数值定义常规桌面工作区中的拖拽下限，不替代已确认的首次默认栏宽比例；
- 单文件资产不显示文件树，也不为文件树保留 160 px，其空间继续自动归入原生内容；
- 当窗口宽度不足以同时满足当前可见栏位的下限时，不继续压缩到下限以下，转而沿用已确认的窄窗口收拢顺序；
- 各栏下限作为窄窗口可用空间判定的输入，不把其简单求和定义为全局固定响应式断点。

辅助栏采用“固定上限，原生内容不设上限”：

- 资产列表上限为 360 px；
- 多文件资产的固定文件树上限为 320 px；
- 辅助检查器上限为 400 px；
- 上述数值是用户主动放大对应辅助栏时的宽度上限，不是默认宽度或建议目标；首次默认栏宽比例保持不变；
- 辅助栏到达上限时，分隔线停止沿扩大该栏的方向继续移动；
- 放大任一辅助栏仍须同时保证其他当前可见栏位不低于各自的可读下限；
- 原生内容不设最大宽度；辅助栏到达上限后，新增可用宽度继续由原生内容吸收；
- 单文件资产不显示文件树，也不为文件树保留其上限空间；
- 本项不改变窄窗口的可用空间判定和收拢顺序。

多文件资产首次打开采用“强内容优先”的默认栏宽基线：

- 资产列表、固定文件树、原生内容和辅助检查器依次约占可用工作区宽度的 16%、14%、52% 和 18%；
- 原生内容默认获得过半宽度，并继续承担主要视觉与编辑焦点；
- 上述比例只定义首次默认状态，不取消已确认的分隔线拖拽调宽；
- 单文件资产不显示文件树，其空间自动归入原生内容；
- 窄窗口和聚焦状态继续按已确认规则临时收拢辅助面板，不改变默认栏宽基线。

用户拖拽形成的栏宽采用“按资产类型跨会话记忆”：

- Skills、长期指令、Subagents 和 Hooks 分别保留各自最近一次常规工作区栏宽，互不套用；
- 用户切换一级资产类型或重新启动应用后，恢复当前资产类型自己的栏宽状态；
- 当前资产类型尚无已记忆状态时，采用已确认的默认栏宽基线；
- 只记忆用户在常规工作区中明确拖拽形成的栏宽；窄窗口自动收拢和原位聚焦产生的临时布局不覆盖该记忆；
- 栏宽记忆的状态存储实现、清理或过期策略另行决定。

恢复默认栏宽的主入口采用“工作区更多菜单”：

- 入口位于当前工作区头部的更多菜单中，以明确的“恢复默认栏宽”语义呈现；
- 该操作不作为工具栏常驻按钮，避免低频管理动作长期占用头部空间并与原生内容竞争注意力；
- 不以分隔线悬浮入口作为主入口；MVP 不为该操作设置默认全局快捷键；
- 恢复默认栏宽只作用于发起操作时的当前一级资产类型；例如在 Skills 工作区触发时，只恢复 Skills 的栏宽记忆，长期指令、Subagents 和 Hooks 保持不变；
- 作用对象是当前资产类型共享的工作区栏宽状态，不是仅恢复当前选中资产的局部布局；
- 当前类型恢复到已确认的默认栏宽基线；用户此后再次拖拽时，以新的栏宽继续更新该类型的跨会话记忆；
- 用户触发后直接执行恢复，不在操作前弹出确认对话框；
- 执行后通过轻量、非模态的结果提示明确当前资产类型已恢复默认，并提供“撤销”操作；
- 撤销精确恢复执行前的栏宽及该资产类型对应的跨会话记忆，不影响其他资产类型；
- 结果提示位于工作区底部居中，不能阻断用户继续浏览或编辑；
- 提示默认显示 8 秒，悬停或键盘焦点进入时暂停计时；
- 提示以 160 ms 轻微上移并淡入或淡出，系统启用减少动态效果时直接切换。

长内容编辑采用“原位上下文聚焦”：

- 聚焦模式由用户显式进入和退出，不在打开资产或进入草稿时自动触发；
- 进入聚焦后，资产列表和辅助检查器临时收窄为可识别的边缘入口，原生内容主区获得更多空间；
- 多文件资产的固定文件树继续可见，当前资产、当前文件路径以及影响安全操作的关键状态继续可见；
- 聚焦仍发生在同一工作区内，不打开独立编辑页、独立窗口或内容独占表面；
- 退出聚焦后恢复进入前的工作区布局，当前资产、当前文件和未应用草稿保持不变。

聚焦入口固定在原生内容工具栏：

- 入口在同一位置以“聚焦 / 退出聚焦”切换，进入和退出不移动到其他菜单或头部区域；
- 入口与原生内容直接关联，不占用工作区头部的全局操作空间；
- MVP 不为“聚焦 / 退出聚焦”设置默认全局快捷键。

窄窗口采用“按可用空间判定、按优先级收拢”：

- 收拢判断以主导航和其他持续占位结构之后，当前工作区真正可供栏位分配的宽度为准，不直接使用应用窗口总宽度；
- 每次判断都基于当前实际可见的栏位组合及各栏已确认的可读下限；单文件资产不显示文件树，因此不计入文件树的下限；
- 不设置一组对所有资产形态通用的固定数值断点；不同栏位组合可以在不同的实际宽度下触发收拢；
- 当现有可见栏位无法同时满足可读下限时，先收拢辅助检查器，再按收拢后的栏位组合和边缘入口重新判断可用空间；
- 若重新判断后仍无法满足剩余栏位的可读下限，再收拢资产列表；
- 该自动判定只响应工作区可用空间或可见栏位组合变化；用户手动拖拽分隔线仍只调整栏宽，不触发自动收拢；
- 被收拢的面板保留可识别入口，用户能够按需查看或恢复完整信息；
- 原生内容继续保持主导，多文件资产的固定文件树、当前资产与文件路径，以及影响安全操作的关键状态继续可见；
- 自动收拢采用 64 px 固定恢复回差：面板收拢后，只有当实际可用工作区达到“恢复该面板后所有当前可见栏位均满足可读下限”的动态临界值，并额外保有 64 px 空间时，才恢复常驻；
- 64 px 是相对于对应动态临界值的恢复缓冲，不是统一的应用窗口或工作区固定断点；
- 可用空间处于动态临界值与恢复线之间时，面板继续保持收拢，边缘入口与覆盖式浮层仍可使用；
- 收拢侧不增加等待缓冲；空间再次不足时仍立即按既定优先级收拢；
- 多个面板同时处于收拢状态时采用分级恢复，并按收拢顺序的逆序处理：资产列表先恢复，辅助检查器随后恢复；
- 两个面板分别遵守自身对应的动态临界值与 64 px 恢复回差；资产列表已经恢复时，辅助检查器不会在尚未达到自身恢复线前一并展开；
- 尚未达到恢复条件的面板继续保持收拢，其边缘入口与覆盖式浮层仍可使用；
- 收拢与恢复不能改变当前资产、当前文件、草稿或检查器上下文；宽度恢复后回到默认常驻布局。

收拢面板采用“覆盖式浮层”临时展开：

- 窄窗口或聚焦状态下，收拢的辅助检查器与资产列表沿用同一展开模型；
- 用户触发可识别的边缘入口后，对应面板从所在侧以浮层覆盖方式临时展开；
- 浮层不加入工作区栏宽分配，也不替换原生内容主区；底层内容的宽度、换行和滚动位置保持不变；
- 打开或关闭浮层不能改变当前资产、当前文件、草稿或检查器上下文；关闭后回到此前的收拢状态；
- 影响安全操作的关键状态继续在页头或对应操作附近可见，不能被浮层遮蔽或隐藏。

收拢面板的常驻入口采用“对应侧边缘轨道”：

- 资产列表的入口固定在工作区左侧边缘，辅助检查器的入口固定在工作区右侧边缘；
- 窄窗口自动收拢与原位聚焦产生的收拢状态沿用同一入口位置和基本形态；
- 入口、面板归属与浮层展开方向保持一致，触发后对应面板从同一侧覆盖式展开；
- 边缘轨道持续可见但不悬浮覆盖原生内容，也不将收拢面板入口集中移动到工作区头部；
- 左右边缘轨道均采用 40 px 固定宽度，以图标和可见短标签“资产”“检查”共同标识，并为触发按钮提供完整无障碍名称；
- 40 px 轨道宽度计入窄窗口的实际可用空间与恢复临界值计算；
- 边缘轨道使用与面板角色对应的图标；常态保持中性，浮层打开时提供柔和激活反馈；
- 仅在存在需要用户处理的异常时显示状态提示，不常驻展示数量；
- 资产列表边缘轨道使用 `Library` 图标，辅助检查器边缘轨道使用 `PanelRightOpen` 图标；
- 禁用时保留角色图标与短标签，通过柔和弱化和悬停或键盘聚焦原因说明表达不可用，不替换为通用禁用图标。

覆盖式浮层采用“记忆宽度受限复用”：

- 在工作区仍能提供对应面板可读下限时，浮层沿用当前一级资产类型中该面板的常规栏宽记忆；
- 浮层宽度同时受已确认的角色下限、角色上限及“最多覆盖实际可用工作区 40%”约束；
- 当前资产类型没有栏宽记忆时，从已确认的默认栏宽基线推导浮层宽度；
- 临时展开不写回或改变常规工作区的跨会话栏宽记忆。

极窄窗口采用“临时解除 40% 覆盖上限”：

- 当 40% 上限不足以提供对应面板的可读下限时，临时解除该上限；
- 浮层扩展到两条 40 px 边缘轨道之间的全部可用宽度，仍保持覆盖式展开，不重排或替换底层原生内容；
- 工作区头部和两侧边缘轨道入口继续可见，用户仍可识别当前上下文并关闭或切换浮层；
- 该降级只在可读下限与 40% 上限冲突时生效，不写回常规工作区的栏宽记忆。

覆盖式浮层采用“头部下方停靠、常规方式关闭、单浮层互斥”：

- 浮层从工作区头部下方开始并停靠到工作区底部，持续保留当前资产、文件路径和影响安全操作的关键状态；
- 浮层提供明确关闭按钮，并支持 `Esc` 与点击浮层外部关闭；
- 关闭后焦点回到触发该浮层的边缘轨道入口；
- 同一时间只允许一个收拢面板浮层保持打开；
- 触发另一侧入口时，新浮层替换旧浮层并将焦点转入新浮层，不同时从两侧遮挡原生内容。

覆盖式浮层采用“160 ms 同侧滑入与滑出”：

- 浮层从所属边缘轨道一侧滑入，并向同一侧滑出，持续时间均为 160 ms；
- 动效不重排底层内容，也不改变底层内容的宽度、换行或滚动位置；
- 系统启用减少动态效果时，直接切换到最终打开或关闭状态。

本项已确认主工作区的信息区结构、宽度调整机制、1 px 视觉线加 8 px 命中区及 8 px 微调、32 px 快调、边界跳转的键盘调宽方式、栏宽拖拽在可读下限停止且不触发收拢、以原生内容为最大保护线的各栏可读下限、辅助栏固定上限且原生内容不设上限、多文件资产默认栏宽基线、按资产类型跨会话记忆栏宽、工作区更多菜单中的恢复默认栏宽主入口、仅作用于当前资产类型的恢复范围、直接执行后提供精确撤销及底部居中 8 秒可暂停提示的反馈模式、原生内容工具栏中的同位聚焦切换、恢复默认栏宽和聚焦均不设置默认全局快捷键、窄窗口按实际可用空间判定并逐级收拢、自动收拢后的 64 px 固定恢复回差、多个面板同时收拢时先资产列表后辅助检查器的分级恢复、收拢面板的覆盖式临时展开、40 px 图标加短标签并按状态反馈的对应侧边缘轨道、`Library` 与 `PanelRightOpen` 角色图标及可解释禁用态、受角色上下限和 40% 上限约束的栏宽记忆复用、极窄窗口临时解除 40% 上限、工作区头部下方至底部的浮层停靠、关闭按钮加 `Esc` 加点击外部的关闭方式及焦点恢复、单浮层互斥替换、160 ms 同侧滑入与滑出并适配减少动态效果；不预设栏宽记忆的状态存储实现、清理或过期策略。

### 7.3 一级入口

- Skills
- 长期指令
- Subagents
- Hooks

一级导航只按上述四类资产组织。项目与 Agent 不作为并列一级入口，而是通过筛选、分组和独立管理入口提供上下文。

### 7.4 列表与检索

每个入口聚合所有已发现的同类资产，并支持至少按以下维度筛选或分组：

- Agent；
- 项目；
- 全局／项目作用域；
- 原生路径或来源层级；
- 可编辑／只读／不兼容状态；
- 正常／覆盖／冲突／漂移状态；
- 转换支持等级。

左侧常驻资产列表默认采用“两行信息增强列表”：

- 第一行以资产名称为主，只附带会改变用户判断的关键异常状态，例如只读、不兼容、冲突或漂移；
- 正常状态不占用固定标签位置，避免每行重复展示低价值信息；
- 第二行展示 Agent、作用域，以及用于区分同名资产的项目或原生路径提示；
- 用户无需先选中资产，即可完成基本识别；选中后再由右侧常驻详情区展示完整信息和操作；
- 列表项不承载长描述或完整快捷操作，避免形成富信息卡片并与右侧详情重复。

资产列表的识别字段采用“Agent 优先的稳定顺序”：

- 第一行继续保持“资产名称 + 关键异常”；
- 第二行固定按 Agent、作用域、项目或原生路径提示排列；
- 优先使用项目名称区分同名资产；没有项目上下文或仍无法区分时，再显示原生路径提示。

长文本采用“名称尾部省略、路径中部省略”：

- 资产名称和项目名称采用尾部省略；
- 原生路径采用中部省略，同时保留起始来源与末端资产段；
- 列表项保持固定两行，不因长文本换行增高；
- 完整值通过悬停或键盘聚焦提示及无障碍文本提供。

默认采用“不分组平铺、按需显式分组”：

- 首次进入资产类型时使用不分组的平铺列表，保持跨 Agent 的资产名称连续可比；
- Agent、项目、作用域、来源或状态等既有维度继续通过显式分组控制按需启用；
- 筛选或搜索不自动套用默认分组。

行内操作采用“整行选择 + 按需单入口”：

- 整行保持资产选择主目标；
- 仅在列表项悬停或键盘聚焦时显示一个“更多”入口，用于次级列表操作；
- 编辑、应用及其他状态变更操作继续位于右侧详情或对应操作区，不在每行常驻。

检索与筛选采用“单一搜索入口 + 显式范围切换”：

- 搜索入口位于当前资产类型的常驻列表内，不在应用头部再设置语义重叠的全局搜索，也不进入独立搜索页；
- 搜索入口附近持续显示范围控件，用户可以在“当前资产类型”和“全部资产”之间显式切换；
- 进入某个一级资产类型时默认检索当前类型，用户需要跨类型定位时再主动切换为全部资产；
- Agent、项目、作用域、来源和状态等筛选继续与搜索同区组织，并与当前搜索范围共同约束列表结果；
- 选择“全部资产”时能够跨 Agent、项目和资产类型定位资产，结果仍在现有资产工作台上下文中呈现；
- 敏感值不得进入搜索索引。

本项已确认资产列表的两行信息密度、字段顺序、长文本截断、默认平铺与按需分组方式、行内操作入口形态，以及单一搜索入口、显式范围切换和筛选同区组织；不预设“更多”菜单的具体操作项。

### 7.5 资产详情

资产详情至少包括：

- 原生内容及结构化信息；
- 实际路径；
- 作用域与生效上下文；
- 加载、覆盖和冲突关系；
- 来源和漂移信息；
- Agent 与适配器兼容状态；
- 最近变更和可用恢复点；
- 可执行的安全操作。

右侧详情区采用“原生内容优先 + 辅助检查器”的主结构：

- 原生内容占据详情区的主要空间，并依据既有编辑边界呈现为结构化编辑、源码编辑或只读内容；
- 辅助检查器位于内容主区一侧，用于查看路径、Agent、作用域、生效上下文、覆盖关系、来源与漂移、兼容状态以及变更和恢复信息；
- 辅助检查器固定常驻，不以可折叠侧栏或覆盖式抽屉作为默认交互；
- 原生内容在宽度分配、信息层级和视觉注意力上保持主导，检查器采用明确的次级视觉层级，不能与内容主区竞争；
- 浏览与编辑共享同一个内容主区，不以概览长页或多个详情标签页作为主要组织方式；
- 选择其他资产时，原生内容主区与辅助检查器在原位同步更新；
- 只读、不兼容、冲突、漂移及其他会影响安全操作的关键状态必须在页头或对应操作附近持续可见，不能只隐藏在辅助检查器深层。

辅助检查器内部采用“关键摘要 + 可展开分组”：

- Agent、作用域、生效上下文和实际路径作为关键摘要持续可见；
- 来源、加载和覆盖关系归入“来源与生效”分组；
- 适配器兼容、漂移和未知内容保留情况归入“兼容与漂移”分组；
- 最近变更和可用恢复点归入“变更与恢复”分组；
- 摘要之外的次级信息按分组展开或收起，不以多个分类标签页或全部默认展开的长列表作为主要组织方式；
- 影响安全操作的关键状态继续显示在页头或对应操作附近，不能因分组收起而消失。

辅助检查器分组采用稳定的“来源 → 风险 → 恢复”顺序：

- 三个分组固定按“来源与生效 → 兼容与漂移 → 变更与恢复”排列；
- 先解释资产从哪里来及如何生效，再呈现兼容风险、最近变更和恢复信息；
- 切换资产或改变展开状态时不动态重排分组。

首次展示采用“关键摘要常驻、次级分组全部收起”：

- 首次显示资产详情时，Agent、作用域、生效上下文和实际路径持续可见；
- “来源与生效”“兼容与漂移”“变更与恢复”三个次级分组全部默认收起；
- 存在异常也不自动展开分组；影响安全操作的关键状态继续在页头或对应操作附近持续可见。

同一资产类型的连续浏览采用“保留当前展开组合”：

- 切换资产后保留当前分组的展开或收起组合，只在原位更新对应内容；
- 该规则支持跨 Agent、项目或作用域连续比较同一类信息；
- 不为每个资产分别记忆展开状态，也不预设跨会话持久化。

实际路径采用“来源锚点 + 单行中部省略路径”：

- 项目资产以项目名称为锚点并显示项目相对路径；
- 全局资产以用户目录或原生全局根为锚点；
- 中部省略同时保留原生目录起点与末端资产段，避免长路径占用多行并削弱原生内容；
- 完整绝对路径通过悬停、键盘聚焦及复制操作提供。

原生内容主区采用“源码默认、结构化按需切换”：

- 打开资产时默认显示当前原生内容的完整源码视图，使注释、未知字段和未结构化内容首先可见；
- 只有适配器能够保证已知字段无损往返时，才提供显式的结构化视图切换；
- 无法安全结构化时不展示伪表单，继续使用源码模式或按兼容策略保持只读；
- 源码与结构化视图继续共享同一份草稿，切换视图不能丢弃未应用修改；
- 两种视图不在内容主区内并排常驻，避免与固定检查器形成三栏并削弱原生内容。

源码与结构化视图采用“内容工具栏内并列切换”：

- 紧凑、带文字的“源码／结构化”切换控件紧邻当前文件或路径上下文；
- 两个选项保持同位可见，打开资产时默认选中源码；
- 不使用会强化独立页面感的内容标签页，也不把替代视图隐藏在单项下拉菜单中；
- 当前资产无法保证安全结构化时，继续在同一位置保留“结构化”不可用项并阻止切换；
- 不可用原因通过悬停、键盘聚焦及无障碍说明提供，不隐藏能力边界，也不让用户点击后才进入阻断死路。

查看态通过“显式进入、原位编辑”进入本地草稿：

- 打开资产时，原生内容默认处于只读查看态，并明确表示当前显示的是磁盘内容；
- 只有用户触发明确的编辑入口后，同一内容主区才原位切换为本地草稿编辑态；
- 进入编辑态不直接写入磁盘，未应用草稿状态必须持续可见；
- 不以打开即直接输入或磁盘原文与草稿并排作为默认编辑入口；
- 只读、不兼容或其他不允许安全编辑的资产不提供可用的编辑入口，并在对应位置说明原因。

显式编辑入口采用“内容工具栏右侧低强调入口”：

- 可编辑资产在原生内容工具栏右侧显示带文字的“编辑资产”入口；
- 入口明确指向完整原生可管理单元，触发后仍在同一内容主区进入本地草稿；
- 编辑不提升为与关键安全状态竞争的页头主操作，也不依赖内容悬停才能发现。

编辑态采用“工具栏内联本地草稿状态”：

- 进入编辑态后，内容工具栏在当前文件或路径上下文附近持续显示“本地草稿”；
- 状态在源码、结构化视图及同一资产内文件切换时保持同位；
- 编辑器几何位置不因状态提示发生跳动，不以常驻横幅或编辑器装饰作为唯一提示。

草稿操作采用“内容工具栏右侧内联”：

- “本地草稿”继续靠近当前文件或路径上下文；
- 工具栏右侧先放低强调的退出或放弃操作，再放主操作“审查更改”；
- 不采用常驻底部操作条，也不把两项操作收进“更多”菜单。

草稿主操作采用“审查更改”：

- 没有实际更改时禁用，并通过悬停、键盘聚焦及无障碍说明解释原因；
- 出现实质更改后启用，进入已经确认的校验、差异、冲突处理与明确确认流程；
- 草稿态不使用会暗示直接写盘的“应用”，也不增加“保存草稿”作为独立前置阶段。

退出与放弃采用“按实际更改决定确认”：

- 没有实际更改时显示“退出编辑”，直接返回查看态且不弹出确认；
- 存在实际更改时显示“放弃草稿”，确认中列出受影响文件与范围；
- “保留草稿”作为高强调的安全默认操作，放弃必须由用户显式选择；
- 放弃只清除应用内本地草稿，不修改磁盘内容。

差异审查采用“同一内容主区原位进入”：

- 以审查内容替换当前编辑器，同时保留当前资产、资产列表、文件树、辅助检查器与关键安全状态；
- 提供明确的“返回草稿”，回到此前草稿上下文；
- 不使用居中模态或独立全屏审查页。

差异默认采用“统一差异”排版：

- 旧行与新行在同一内容列按顺序显示，以行号及新增、删除标记区分；
- 完整内容主区宽度继续优先服务原生内容；
- MVP 不默认并排，也不增加统一与并排之间的模式切换。

多文件审查继续复用真实文件树：

- 发生变化的文件显示关键更改标记与增删摘要；
- 进入审查时，当前文件已有更改则保持选中，否则定位稳定树序中的首个更改文件；
- 未变文件仍可选择，以核对同一原生资产的上下文；
- 不改用仅含更改文件的扁平清单，也不把全部文件差异连续铺开。

差异上下文采用“变更行 + 邻近原文上下文”：

- 长段未变内容折叠为带范围说明的可展开区段；
- 用户可以在原位展开或收起未变区段；
- 不默认展示完整文件，也不移除判断变化所需的上下文。

审查摘要采用紧凑的两层结构：

- 审查工具栏显示整个资产的更改文件数、增删量与关键校验状态；
- 当前文件标题附近显示路径及该文件的增删量；
- 不使用会压过原生差异的摘要卡组，也不完全省略影响规模摘要。

多文件原生资产采用“内容区内固定文件树”：

- 资产包含多个原生文件时，在原生内容主区内、当前文件内容一侧固定展示文件树，并按真实目录层级组织；
- 选择文件只在原位切换当前内容，不改变左侧资产选择、辅助检查器上下文或原生资产边界；
- 文件树只承担同一资产内部的内容导航，不把单个物理文件提升为独立资产；
- 切换文件不能丢弃同一资产中其他文件的未应用修改，草稿、校验、差异预览与事务状态仍以完整原生可管理单元为边界；
- 单文件资产不展示空文件树，继续让原生内容占据主区。

文件树采用“单行名称 + 关键状态”的紧凑密度：

- 文件或目录名称作为每行主信息；
- 只附带未应用修改、不可预览或其他会影响判断的关键状态，文件级提示不改变完整资产的草稿与事务边界；
- 不常驻重复展示相对路径、类型、大小或修改时间，完整路径继续由内容工具栏和辅助检查器提供。

目录初始展开采用“只展开当前路径”：

- 首次显示当前文件时，资产根目录及当前文件的祖先目录自动展开；
- 其他无关目录默认收起；
- 用户后续手动展开或收起目录时，不因选择其他文件而自动收回其操作。

多文件资产的默认文件采用“主文件优先、稳定文本兜底”：

- 首次进入多文件资产且没有仍有效的当前文件时，优先选择适配器明确识别的主文件；
- 没有明确主文件时，选择稳定树序中的首个可预览文本文件；
- 不恢复跨会话的最后查看文件，也不先插入非原生的资产概览页。

不同文件类型采用“文本源码、非文本只读元数据”：

- 可预览文本文件继续在同一内容主区使用源码视图，并仅在既有兼容与编辑边界允许时进入编辑；
- 非文本或未知文件仍可在文件树中选择；
- 非文本或未知文件只显示文件类型、大小、原生路径和不可预览或不可编辑原因等只读元数据；
- MVP 不新增媒体渲染、原始字节或十六进制编辑器。

### 7.6 搜索索引一致性

搜索索引是可丢失、可重建的查询加速层，不是资产事实来源。MVP 采用“增量监听 + 有界校准”：

- 目录首次纳入管理时，为授权范围建立本地派生索引；
- 只监听已经确认管理的目录，合并高频文件事件后增量更新对应索引；
- 应用启动、恢复前台及周期性校准时，对已授权范围执行有界一致性检查；
- 文件监听溢出、Git 批量切换或其他无法确认索引状态的情况发生时，将受影响范围明确标记为“索引可能过期”，并触发重新扫描；
- 索引重建完成后原子切换，不能向用户展示新旧数据混合的中间状态；
- 搜索结果展示最近更新时间和索引过期状态；
- 创建、编辑、转换、删除及恢复等写入操作开始前，必须重新读取并校验磁盘当前状态，不得依赖搜索索引执行变更；
- 索引不得越出用户授权范围，敏感值继续按第 14 节排除。

具体监听延迟、校准周期、可支持资产规模和性能目标，由技术方案阶段基于真实样例测量确定。

## 8. 创建、导入、编辑与导出

### 8.1 原生创建

- 用户从四类资产入口发起创建。
- 创建时明确目标 Agent、项目、作用域和原生位置。
- 适配器提供版本化的最小原生模板。
- 不通过跨 Agent 通用 Schema 创作一份中央定义。

### 8.2 本地导入

- 支持导入本地文件、Skill 目录或适配器明确支持的配置片段。
- 导入是一次性的复制与安装。
- 导入后，目标原生资产成为唯一事实来源。
- 导入源不存在不会影响目标资产使用。

创建与导入采用“并列入口 + 内容主区原位承载”：

- “新建”和“从本地导入”在当前资产类型工作区的操作区同位可见，保持为两个语义明确的并列入口，不合并为需要二次选择的单一入口；
- 发起后保留当前一级资产类型、资产列表及工作区上下文，以原生内容主区原位承载目标设置和本地草稿；
- 创建或导入过程中明确目标 Agent、项目、作用域和原生位置，不以离开工作台的全屏向导作为默认路径；
- 文件或目录选择、兼容提示和目标校验继续在同一流程内完成，不把主要流程压入居中模态；
- 目标设置完成后直接进入既有本地草稿、校验、差异审查和事务式应用流程。

### 8.3 原生结构化编辑 + 源码兜底

- 适配器明确理解且能保证无损往返的原生字段，可提供结构化编辑。
- Markdown 正文、Prompt、Hook 代码和未知扩展内容使用源码编辑器。
- 修改已知字段时必须保留未知字段、注释、顺序及原生格式。
- 无法保证无损往返时自动退化为源码模式。
- 结构化视图与源码视图共享同一份草稿。
- 未经验证的配置结构在两种视图中均保持只读。
- 不为了展示表单而重新序列化整个文件。

| 资产 | 可结构化部分示例 | 源码部分示例 |
|---|---|---|
| Skills | 元数据、路径、依赖 | `SKILL.md` 正文及附属脚本 |
| 长期指令 | 作用域、加载关系 | Markdown 正文 |
| Subagents | 名称、模型、工具、权限 | Prompt 与扩展配置 |
| Hooks | 事件、命令、超时、匹配条件 | 脚本或插件代码 |

### 8.4 原生资产导出

- MVP 只提供选中原生资产的导出。
- 按原始文件或目录结构复制到用户指定位置，不生成产品私有格式。
- 导出前提示原生资产可能包含敏感值或可执行脚本。
- MVP 不生成诊断包；导出入口与内部边界应允许后续独立增加隐私保护的诊断导出能力。

## 9. 确定性跨 Agent 转换

### 9.1 产品定义

跨 Agent 转换是 MVP 的核心差异化能力，但不接入 LLM，不要求 API Key，也不产生模型调用成本。

其定义为：

> 解析源 Agent 的已知原生资产，通过版本化规则与模板映射，生成并验证目标 Agent 的原生资产，同时报告能力映射、损失、风险与阻断原因。

转换后的目标资产是独立副本，不与源资产持续同步。

MVP 中每次转换限定为“一个源资产 → 一个目标 Agent 的一个作用域”。用户需要向多个 Agent 或项目安装同一资产时，必须分别发起、预览和确认，不提供一对多写入。

转换采用“同一内容主区内的分阶段流程”：

- 发起转换后继续保留源资产、资产列表和辅助检查器，使源 Agent、作用域、路径及兼容上下文持续可见；
- 原生内容主区依次承载目标设置、能力映射报告和差异审查三个明确阶段；
- 能力映射报告集中展示保留、改写、缺失、人工处理和阻断项，并明确完整、降级或阻断结论；
- 完整或允许继续的降级转换进入既有差异审查；阻断转换停留在可解释报告，不生成可应用结果；
- 转换不使用居中模态向导，也不建立要求重新选择源资产的独立转换中心。

### 9.2 验收标准

MVP 采用“可验证的原生转换”标准：

- 格式与结构有效；
- 目标字段、路径和引用通过确定性校验；
- 能力映射过程可解释；
- 明确列出保留、改写、缺失和待人工处理内容；
- 明确标记不确定性与风险；
- 用户确认后才允许写入目标位置。

产品不承诺源 Agent 与目标 Agent 的最终行为完全等价。

### 9.3 全矩阵可分析

四个 Agent、四类资产共有 48 条有方向的跨 Agent 逻辑路径。所有组合均可发起分析，结果分为：

| 等级 | 含义 | 是否允许写入 |
|---|---|---|
| 完整转换 | 已知能力全部映射，目标结构与校验通过 | 允许确认后写入 |
| 降级转换 | 目标结构有效，但存在明确缺失、替代或人工处理项 | 风险确认后写入 |
| 阻断转换 | 目标缺少必要能力，或无法证明转换安全 | 不允许写入 |

“阻断”是可信转换系统的正常结果，不视为引擎异常。

### 9.4 转换引擎原则

- 每个 Agent 使用独立、版本化的解析器与生成器。
- 可以使用内部、临时、强类型的中间模型降低组合复杂度。
- 中间模型不是用户可见或持久化的统一 DSL，也不成为事实来源。
- 每条规则声明源 Agent、目标 Agent、版本范围、资产类型和能力边界。
- 相同输入必须产生相同输出。
- 重复转换必须具备幂等性，不能反复改变结果。
- 长期指令正文原则上原样保留，或仅执行有明确定义的机械改写。
- 不声称能够通过规则理解和重构任意自然语言语义。
- Hooks 只转换白名单事件与已知安全代码模式。
- 未知字段、事件、权限或能力一律降级或阻断。

### 9.5 校验链路

转换输出依次经过：

1. 目标原生结构校验；
2. 字段与类型校验；
3. 路径及作用域校验；
4. 当前转换结果内已知引用字段的静态校验；
5. 目标 Agent 能力校验；
6. 敏感信息处理校验；
7. 静态安全校验；
8. 差异预览与风险报告；
9. 用户确认；
10. 事务式写入。

## 10. 兼容性策略

### 10.1 已验证兼容范围

每个适配器声明经过测试的：

- Agent 版本范围；
- 原生配置结构；
- 四类资产能力范围；
- 可读、可编辑和可转换边界。

### 10.2 运行时状态

| 状态 | 产品行为 |
|---|---|
| 已验证兼容 | 开放被明确覆盖的管理与转换能力 |
| 可识别但未经验证 | 只读展示、备份和导出；禁止结构化修改与转换 |
| 未知或不兼容 | 明确提示并封闭失败 |

Agent 刚升级而适配器尚未验证时，短期只读是可接受的产品取舍。

### 10.3 回归保障

需要建立：

- 四 Agent × 四类资产的固定样例库；
- 各版本解析与生成的黄金结果；
- 48 条逻辑转换路径的分析回归；
- 完整、降级、阻断结果的固定用例；
- 未知字段、未知版本和损坏配置的失败隔离用例；
- 幂等性、注释保留和格式保留用例。

Agent 格式发生未知变化时，不猜测、不静默兼容。

### 10.4 首发平台范围

MVP 仅正式支持 macOS，并完整实现、验证以下平台相关能力：

- Agent 安装及标准目录发现；
- 文件权限、符号链接和路径规范化；
- 文件监听、文件锁与原子写入；
- 系统废纸篓与可恢复删除；
- 钥匙串及敏感快照加密。

Windows 和 Linux 不进入 MVP 的可用性承诺，也不提供未经完整验证的实验支持。为避免平台边界固化：

- 平台相关能力必须通过明确接口隔离；
- 核心解析、转换和校验逻辑保持平台无关；
- 业务层不得硬编码 macOS 路径或平台行为；
- 后续平台适配必须沿用已验证兼容范围、封闭失败和全量回归原则。

### 10.5 适配器与转换规则发布

MVP 采用官方签名、可验证、可回滚的适配器包独立更新机制：

- 应用内置一套经过验证的适配器与规则，离线情况下仍可使用内置版本；
- 核心解析、转换、校验和沙箱边界由应用执行引擎提供，仍随应用正式版本发布；
- 可独立更新的适配器包只包含声明式 Schema、能力矩阵、路径定义、模板及受限转换规则，不得包含或加载任意可执行代码；
- 每个适配器包必须声明自身版本、应用兼容范围、Agent 兼容范围、原生结构版本、规则版本和所需引擎能力；
- 包体必须经过官方签名与完整性校验；签名无效、来源不可信、清单不完整或兼容范围不匹配时封闭失败；
- 下载后先在隔离的候选槽位执行固定样例、黄金结果、幂等性和失败隔离回归，通过后才允许启用；
- 启用采用原子切换，不在同一次操作中混用新旧组件；
- 始终保留上一可用版本；启用后出现问题时可以一键回滚；
- 下载、校验或启用失败不得影响当前正在使用的适配器；
- 默认自动检查官方更新，但安装前必须展示兼容范围、能力和规则变化，由用户确认后安装；
- 更新或回滚均须记录确切包版本，以保证转换结果可追踪和问题可复现；
- 不允许用户安装自定义规则、第三方规则包、社区适配器或绕过签名与兼容检查；
- 不能由声明式包安全表达的解析或转换能力，必须等待包含相应引擎能力的新应用版本，不得通过适配器包引入代码执行入口。

独立更新的目的，是缩短 Agent 升级后的只读窗口；它不改变已验证兼容范围、默认封闭失败和官方可信供应链原则。

## 11. 变更事务与并发控制

### 11.1 统一变更流程

所有创建、导入、编辑、转换和安装操作进入同一事务流程：

1. 生成本地草稿；
2. 执行适配器与安全校验；
3. 展示文件、配置块和影响上下文差异；
4. 处理重名与目标冲突；
5. 用户明确确认；
6. 基于写入前最新磁盘状态创建快照；
7. 在临时位置生成并校验；
8. 原子应用；
9. 失败时回滚；
10. 记录不含敏感值的操作结果。

重名时不得静默覆盖。至少需要支持取消、改名或预览差异后覆盖。

差异审查后的事务采用“审查主操作 + 聚焦确认 + 原位结果”收口：

- 差异审查中的主操作使用“应用更改”，不允许从草稿态绕过完整差异直接写入；
- 触发后在当前审查工作区进入聚焦确认，集中核对目标 Agent、项目或作用域、原生路径、Git 工作树状态和即将创建的恢复点；
- 聚焦确认不替换为独立事务向导，用户可以返回差异审查且不丢失当前文件、展开状态或草稿上下文；
- 应用前若检测到外部变化或无法安全合并的冲突，同一内容主区切换为三方差异并按第 11.2 节处理；
- 应用成功后在原位展示操作结果及可用恢复点；失败时原位说明阻断或回滚结果，不只依赖短暂提示反馈。

### 11.2 乐观并发控制

打开资产时记录基线内容与哈希，应用前再次核对磁盘状态：

- 文件未变化：正常进入事务式应用；
- 外部变化与当前草稿可确定性合并：重新生成差异预览；
- 存在重叠或无法证明安全：阻断写入；
- 冲突时展示基线、磁盘当前版本和应用草稿的三方差异；
- 用户可保留草稿、手动解决冲突或放弃；
- 快照始终基于写入前的最新磁盘版本；
- 任何情况下都不得静默覆盖 IDE、Git 或 Agent CLI 产生的外部修改。

### 11.3 可恢复删除

删除属于受保护的变更事务，不允许绕过预览、确认和恢复机制：

- 独立文件或目录优先移入操作系统废纸篓，不直接永久删除；
- 配置块删除前先快照完整宿主文件，再事务式移除目标配置块；
- 删除界面必须展示原生资产边界、目标路径和受影响的生效上下文；
- 恢复时若原路径或配置位置已被占用，必须展示差异并阻断静默覆盖；
- 恢复操作同样受版本兼容、并发检查、敏感信息保护和原子写入约束；
- 外部工具删除资产时，产品只将其标记为缺失，不自动重新创建；
- 永久清理系统废纸篓不属于单次资产删除操作；应用私有快照按第 11.5 节的有界策略保留和清理。

### 11.4 Git 状态感知

当资产位于 Git 仓库中时，产品感知并展示 Git 状态，但不操作 Git：

- 识别资产所属仓库及其仓库相对路径；
- 写入前展示目标文件的已修改、未跟踪、忽略等状态；
- 区分应用草稿差异、当前工作树差异与应用私有快照；
- 应用快照只承担事务恢复职责，不冒充 Git 版本历史；
- 恢复快照仍须基于当前磁盘状态生成差异并由用户确认；
- Git checkout、merge、rebase 等造成的变化统一视为外部文件变化，并通过文件监听与乐观并发控制处理；
- 不执行暂存、提交、stash、分支切换、合并、rebase 或 Git 回退；
- 不要求纳入管理的项目必须使用 Git。

Git 只作为修改风险和版本上下文展示，不成为 MVP 的写入执行层。

### 11.5 快照保留与清理

应用快照只承担事务恢复职责，采用“有界自动保留 + 手动固定”策略：

- 每次写入前都必须基于最新磁盘状态创建有效快照；
- 同时设置保留周期与应用级全局容量上限，具体默认值在技术方案阶段通过真实资产样例测量确定；
- 达到周期或容量限制时，只能自动清理最旧且未固定的快照；
- 每项资产至少保护最近一个有效恢复点，不得因全局清理而失去全部恢复能力；
- 用户可以固定重要快照，固定项不参与自动清理；
- 事务未完成、回滚中或恢复中的快照不得清理；
- 磁盘空间不足、快照创建失败或无法验证快照完整性时，阻断本次写入；
- 固定快照占满容量时，要求用户清理固定项或提高容量上限，不允许绕过快照继续修改；
- 含敏感值的快照继续受第 14 节的加密与安全存储约束；
- 自动清理必须留下不含敏感值的可审计结果，并且不能影响任何 Agent 原生资产。

### 11.6 单资产、单目标事务

MVP 的变更操作以单资产、单目标为事务边界：

- 每次只创建、导入、编辑、转换、安装、删除或恢复一个原生资产；
- Skill 目录、带附属脚本的资产等多文件原生可管理单元，整体仍视为一个资产和一个原子事务；
- 跨 Agent 转换限定为一个源资产写入一个目标 Agent 的一个作用域；
- 可以批量选择资产用于查看、比较或原生导出，但不提供批量写入、批量删除、批量安装或一对多转换；
- 同一操作不会产生跨目标的部分成功状态，也不需要执行跨资产或跨目标的联合回滚；
- 内部事务接口应保留未来编排多个独立事务的能力，但该编排能力不进入 MVP 的产品入口和验收范围。

### 11.7 跨资产依赖边界

MVP 只校验当前操作的原生资产，不分析或维护资产之间的依赖关系：

- 不建立跨资产依赖图或引用索引；
- 不扫描哪些其他资产引用了当前资产；
- 重命名、移动、删除或修改资产时，不计算受影响资产，也不因潜在的跨资产引用断裂而阻断操作；
- 不自动修改、修复或级联更新其他资产；
- 适配器仍可对当前资产内部的已知引用字段执行静态格式校验，但该校验不扩展为跨资产关系管理；
- 跨资产引用是否仍然有效，由用户或目标 Agent 的原生机制负责。

未来如需依赖感知，应作为独立能力扩展，不改变 MVP 的单资产事务模型。

## 12. 来源、漂移与辅助元数据

### 12.1 记录来源但不自动同步

对于导入或转换产生的目标资产，应用私有索引可记录：

- 来源路径；
- 导入或转换时间；
- 源与目标哈希；
- 适配器和转换规则版本；
- 最近一次转换结论；
- 源变化与目标手工修改状态。

产品可以提示“源已变化”或“目标已修改”，并允许重新生成转换草稿与差异预览，但：

- 不后台同步；
- 不自动更新；
- 不静默覆盖；
- 不建立持续主从关系。

### 12.2 应用私有本地存储

所有辅助元数据、操作记录和快照索引保存在应用私有本地存储中：

- 不在用户项目中自动创建隐藏目录或 sidecar 管理文件；
- 数据库不成为原生资产的事实来源；
- 卸载应用或删除数据库不删除、禁用或改变任何原生资产；
- 数据库丢失后可重新扫描原生目录恢复资产索引；
- 来源关系、历史操作等不可推导信息可能无法恢复；
- 快照按保留周期、全局容量上限、固定状态和每资产最低恢复点进行有界管理。

MVP 不处理项目元数据同步或团队共享。

## 13. 可执行资产安全边界

MVP 对 Hook、Skill 脚本和插件代码只做静态校验，产品自身绝不执行：

- 扫描、预览和转换过程不得触发代码；
- 安装前展示完整命令、脚本路径、事件和影响范围；
- 对外部导入的可执行资产明确标记风险；
- 校验解释器、路径、引用、权限和已知危险模式；
- 不保证脚本运行结果；
- 写入后由目标 Agent 的原生机制决定何时和如何执行。

MVP 不建设跨平台沙箱，也不在用户环境中直接试运行资产代码。

## 14. 敏感信息保护

MVP 不成为凭证管理器，但对不可避免接触的敏感内容实施强制保护：

- 默认遮蔽 API Key、Token 和其他已识别敏感值；
- 只有用户显式操作时才能临时查看或修改；
- 敏感值不进入搜索索引、操作日志、诊断信息或来源元数据；
- 差异预览默认只显示“敏感值发生变化”，不展示明文；
- 优先识别和保留环境变量等原生引用；
- 跨 Agent 转换只转换引用关系，不复制明文密钥；
- 原生文件中已有的敏感值作为不透明内容无损保留；
- 完整恢复所需快照必须加密；
- 快照加密密钥由操作系统安全存储管理；
- 无法获得安全存储能力时，对含敏感值资产的修改封闭失败。

MVP 不提供密钥创建、轮换、同步或注入服务。

## 15. MVP 核心闭环

MVP 应形成以下完整闭环：

```mermaid
flowchart LR
    A["发现原生资产"] --> B["解析生效上下文"]
    B --> C["创建 / 编辑 / 导入 / 转换"]
    C --> D["校验与差异预览"]
    D --> E["事务式写入"]
    E --> F["来源、漂移与恢复"]
    F --> A
```

闭环中的任何写入都受兼容范围、封闭失败、敏感信息保护和并发控制约束。

## 16. MVP 验收原则

### 16.1 发现与上下文

- 能以资产类型为主入口聚合四类资产；
- 同一原生资产不会因多个上下文可见而重复；
- 能展示路径、Agent、作用域、来源层级和生效状态；
- 能识别适配器无法确认的上下文并明确标记。
- 能自动发现受支持 Agent 的标准全局目录，但项目级目录必须由用户显式纳入；
- 能以只读方式展示受支持 Agent 的安装状态、已解析安装路径和版本；
- Agent 发现过程不会安装、升级或卸载 Agent，也不会调用包管理器或修改系统运行时配置；
- 父目录扫描只产生待确认候选，不自动管理扫描结果；
- 后台监听不越出已确认目录，符号链接也不得扩大授权边界；
- 移除项目不会改变原生资产，路径失效也不会触发自动重建。
- 已授权范围内的外部文件变化能够通过增量监听进入索引；
- 监听溢出、Git 批量切换或一致性不确定时，受影响范围会显示过期状态并执行有界重建；
- 索引重建采用原子切换，不会向用户暴露新旧数据混合的搜索结果；
- 搜索结果能够展示最近更新时间和索引过期状态；
- 所有写入、删除和恢复操作均重新读取磁盘，不把索引内容作为写入依据；
- 搜索索引不包含授权范围外内容或敏感值。

### 16.2 编辑与数据保真

- 已知结构可安全编辑；
- 未知字段、注释、顺序和原生格式不被静默破坏；
- 无法保证无损往返时退化为源码或只读；
- 外部并发修改不会被静默覆盖。

### 16.3 转换

- 所有逻辑路径均可发起分析；
- 每次分析得到完整、降级或阻断的明确结论；
- 相同输入与规则版本得到相同输出；
- 重复执行不产生持续漂移；
- 转换报告能够解释能力映射、缺失和风险；
- 未覆盖能力不被猜测性生成；
- 每次转换只写入一个目标 Agent 的一个作用域，不存在未经分别预览和确认的一对多安装。

### 16.4 写入与恢复

- 所有写入前均有校验、差异预览和用户确认；
- 写入前创建最新状态快照；
- 写入采用临时生成、原子应用和失败回滚；
- 任意失败不会留下部分写入或损坏状态；
- 独立文件或目录删除后可从系统废纸篓恢复；
- 配置块删除可基于完整宿主文件快照恢复；
- 恢复目标被占用时不得静默覆盖；
- 外部删除只标记为缺失，不触发自动重建；
- 自动清理仅处理最旧且未固定的快照，并为每项资产至少保留最近一个有效恢复点；
- 固定快照不会被自动清理，未完成事务及恢复中的快照也不会被清理；
- 磁盘空间不足、必要快照创建失败或固定快照占满配额时，产品阻断写入而非绕过保护；
- 位于 Git 仓库中的资产在写入前可见其工作树状态；
- 应用能够区分自身草稿差异、Git 工作树差异和事务快照；
- 任何资产操作均不会隐式执行 Git 暂存、提交、stash、分支切换或回退；
- 每次变更只以一个原生资产和一个目标为事务边界；多文件原生资产仍能作为整体原子应用；
- 产品不存在批量写入、批量删除、批量安装或跨目标部分成功状态。
- 单资产变更不会扫描或修改其他资产，也不会建立依赖图、执行断裂影响分析或级联更新。

### 16.5 安全

- 产品扫描和校验不会执行资产代码；
- 敏感值不进入索引、日志、诊断和来源元数据；
- 含敏感值快照得到加密保护；
- 未知版本、未知格式和不兼容能力封闭失败。

### 16.6 平台

- MVP 在受支持的 macOS 版本上完成平台相关能力的端到端验证；
- 核心解析、转换和校验测试不依赖 macOS 专属实现；
- 平台能力均通过可替换接口访问，业务层不存在硬编码平台路径；
- Windows 和 Linux 不被标记为可用或实验支持。

### 16.7 发布一致性

- 任一操作和转换结果都能确定其应用引擎、适配器包、Schema、能力矩阵、规则和模板的准确版本；
- 官方适配器包必须通过签名、完整性、应用兼容范围和 Agent 兼容范围校验；
- 候选包启用前必须完成适用的黄金样例、全矩阵、幂等性和失败隔离回归；
- 适配器切换为原子操作，失败不会改变当前可用版本，也不会产生新旧规则混用状态；
- 产品始终保留上一可用包，并能在不修改原生资产的前提下回滚；
- 默认自动检查更新，但未经用户确认不得安装或改变转换行为；
- 适配器包不包含任意可执行代码，无法安全声明化表达的能力只能通过应用升级交付；
- 不存在安装自定义规则、第三方或社区规则包，以及绕过签名、兼容范围或回归检查恢复写入的入口；
- Agent 未知版本保持只读，直至兼容的官方适配器包或应用引擎完成验证并发布。

### 16.8 导出

- 能将选中的原生资产按原始文件或目录结构导出到用户指定位置；
- 不生成产品私有资产包、诊断包或完整环境备份；
- 导出包含敏感值或可执行脚本时，用户在操作前可见明确提示。

具体性能目标、覆盖率阈值，以及快照默认容量、保留周期和告警阈值的数值待技术方案阶段通过真实样例测量确定，不在本文中预设未经验证的数字。

## 17. 对技术架构的直接约束

后续技术方案至少需要包含以下模块边界：

- 只读 Agent 发现与版本检测，以及与未来生命周期管理能力相隔离的扩展边界；
- 四个独立、版本化的 Agent 适配器；
- 原生资产扫描器与身份解析；
- 生效上下文解析器；
- 原生结构保真的编辑层；
- 临时强类型转换中间模型；
- 规则、模板与能力矩阵；
- 官方适配器包清单、签名验证、兼容性判定与候选版本管理；
- 适配器包回归验证、原子启用与上一可用版本回滚；
- 静态校验与敏感信息识别；
- 差异预览与三方冲突解决；
- 单资产、单目标事务，以及可供未来编排但在 MVP 中不暴露的事务接口；
- 快照、原子写入与回滚；
- 快照配额、固定状态、最低恢复点与安全清理；
- 可恢复删除与恢复冲突处理；
- Git 仓库识别、状态读取与差异上下文展示；
- macOS 平台能力实现与可替换的平台抽象层；
- 应用私有元数据、来源和漂移索引；
- 增量文件监听、索引状态管理、有界校准与原子重建；
- 原生资产导出，以及与未来诊断导出相隔离的扩展边界；
- 资产类型优先的检索与管理界面。

这些模块不得改变“原生资产为唯一事实来源”的产品原则。
MVP 技术架构不包含跨资产依赖图、引用索引、影响分析器或级联重构引擎；相关能力仅保留后续独立扩展的可能性。

| 收拢面板常驻入口 | 采用对应侧边缘轨道：资产列表位于左侧、辅助检查器位于右侧；不覆盖原生内容，也不集中移动到工作区头部 |
| 边缘轨道规格 | 左右轨道均为 40 px；图标与可见短标签“资产”“检查”共同标识，触发按钮具有完整无障碍名称 |

| 详情区主结构 | 原生内容优先 + 辅助检查器；其他信息辅助呈现，影响安全操作的状态持续可见 |
| 辅助检查器 | 固定常驻侧栏；原生内容在宽度、信息层级和视觉注意力上保持主导 |
| 检查器信息组织 | Agent、作用域、生效上下文和路径作为常驻摘要；来源与生效、兼容与漂移、变更与恢复按需展开 |
| 检查器分组顺序 | 来源与生效 → 兼容与漂移 → 变更与恢复；切换资产或展开分组时不动态重排 |
| 检查器默认展开 | 关键摘要常驻，三个次级分组首次全部收起；关键安全状态不依赖分组展开 |
| 检查器跨资产展开状态 | 同一资产类型连续浏览时保留当前展开组合并原位更新内容；不按资产分别记忆，也不预设跨会话持久化 |
| 检查器实际路径 | 来源锚点 + 单行中部省略；项目显示项目相对路径，全局显示相对用户目录或原生全局根的路径，完整绝对路径按需提供 |
| 原生内容默认视图 | 源码默认、结构化按需切换；两种视图共享草稿且不并排常驻 |
| 内容视图切换 | 内容工具栏内并列显示“源码／结构化”，紧邻文件或路径上下文；打开资产时默认选中源码 |
| 结构化不可用态 | 保留不可用项并阻止切换，通过悬停、键盘聚焦及无障碍说明解释原因 |
| 编辑草稿入口 | 默认只读查看磁盘内容；用户显式进入编辑后在同一内容主区创建本地草稿 |
| 编辑入口位置 | 原生内容工具栏右侧使用低强调、带文字的“编辑资产”入口，明确指向完整原生可管理单元 |
| 编辑态草稿状态 | 工具栏在文件或路径上下文附近持续显示“本地草稿”，跨视图与同一资产内文件切换保持同位且不改变编辑器几何位置 |
| 草稿操作区 | 内容工具栏右侧内联；低强调的退出或放弃在前，主操作“审查更改”在后 |
| 草稿主操作 | 使用“审查更改”；无实际更改时可解释禁用，有更改时进入既有校验、差异、冲突处理与确认流程 |
| 退出与放弃确认 | 无实际更改时直接退出编辑；有更改时列明影响并确认放弃，以保留草稿为安全默认操作 |
| 差异审查进入方式 | 在同一内容主区原位替换编辑器，保留资产、文件树、检查器与安全上下文，并可返回草稿 |
| 差异默认排版 | 统一差异；旧行与新行在同一内容列按顺序显示，不提供并排默认或排版切换 |
| 多文件审查导航 | 复用真实文件树并标记更改；优先保持已更改当前文件，否则定位首个更改文件 |
| 差异上下文密度 | 变更行加邻近原文上下文；长未变区段折叠且可原位展开 |
| 审查摘要层级 | 工具栏显示资产级更改与校验摘要，当前文件标题附近显示路径及文件级增删量 |
| 多文件资产内容导航 | 原生内容主区内固定显示真实目录文件树；切换文件不改变资产与事务边界 |
| 文件树信息密度 | 单行显示文件或目录名称，仅附带未应用修改、不可预览等关键状态；路径与其他元数据不常驻重复 |
| 文件树默认展开 | 首次展开资产根目录与当前文件的祖先目录，其他目录默认收起；不自动撤销用户后续展开状态 |
| 多文件默认文件 | 无有效当前文件时优先选择适配器识别的主文件，否则选择稳定树序中的首个可预览文本文件 |
| 非文本文件预览 | 文件仍可选择，但仅显示类型、大小、原生路径及不可预览或不可编辑原因等只读元数据 |
| 一级导航 | Skills、长期指令、Subagents、Hooks；项目与 Agent 作为筛选、分组及管理维度 |
| 资产粒度 | 原生可管理单元 |
| 创建与导入 | 原生创建 + 本地导入 |
| 创建与导入承载 | “新建”与“从本地导入”同位并列可见；在原生内容主区原位完成目标设置并形成草稿 |
| 编辑方式 | 能无损才结构化，否则源码兜底或只读 |
| 跨 Agent 能力 | 确定性规则与模板转换，不使用 LLM |
| 跨 Agent 转换流程 | 保留源资产与检查器，在同一内容主区依次完成目标设置、能力映射报告和差异审查 |
| 转换标准 | 结构有效、过程可解释，不承诺行为等价 |
| 转换矩阵 | 全矩阵可分析；完整、降级、阻断三级结果 |
| 失败策略 | 默认封闭失败 |
| 兼容策略 | 已验证版本可写，未经验证版本只读或阻断 |
| 来源关系 | 记录来源与漂移，不自动同步 |
| 辅助元数据 | 应用私有本地存储，不污染用户项目 |
| 可执行资产 | 只做静态校验，产品绝不执行 |
| 凭证边界 | 不托管凭证，但强制保护敏感内容 |
| 写入方式 | 预览、确认、快照、原子应用、失败回滚 |
| 审查后事务收口 | 从差异审查发起“应用更改”，聚焦确认目标、路径、Git 状态与恢复点；冲突及结果在原位处理 |
| 并发修改 | 乐观并发控制；无法安全合并则阻断并三方解决 |
| 删除策略 | 可恢复删除；独立资产优先移入系统废纸篓，配置块基于宿主文件快照恢复 |
| 项目发现 | 有界发现 + 显式纳入；仅监听已确认目录，不扫描整个主目录或磁盘 |
| 项目移除 | 仅停止管理，不删除或修改原生资产 |
| Git 边界 | 感知并展示仓库与工作树状态，但绝不替用户操作 Git |
| 首发平台 | MVP 仅正式支持 macOS；核心逻辑平台无关并保留跨平台扩展接口 |
| 适配器与规则发布 | 官方签名的声明式适配器包可独立更新；启用前验证、原子切换、保留上一可用版本，MVP 不开放第三方扩展 |
| 快照保留 | 有界自动保留 + 手动固定；每资产至少保留最近一个有效恢复点，必要快照无法创建时阻断写入 |
| 搜索索引 | 增量监听 + 有界校准；状态不确定时标记过期并原子重建，写入前始终重新读取磁盘 |
| 导出边界 | MVP 只提供原生资产导出；不生成诊断包，保留后续独立扩展能力 |

### 20.5 统一视觉规范（已确认）

统一交互原型已覆盖资产浏览、原生内容查看、源码与结构化切换、本地草稿、统一差异审查、聚焦确认、原位结果，以及跨 Agent 转换主链路。用户于 2026-07-26 全部接受统一视觉规范，未提出需要重新打开产品级决策的核心例外。

本节把可由既有决策直接推导的视觉细节合并为一次集中验收，现已写入“已确认决策索引”。

#### 字体与信息层级

- 界面文字采用 macOS 优先的系统无衬线字体栈；源码、原生路径、差异和命令采用系统等宽字体栈；
- 产品标题使用 20 px / 500，分区标题 16 px / 500，正文 14 px / 400，辅助信息 13 px / 400；
- 只使用 400 与 500 两档字重，不依赖多档粗细制造层级，也不把关键正文压缩到 12 px 以下；
- 信息层级优先通过位置、对齐、间距和内容关系建立，避免用大字号或强装饰与原生内容争夺注意力。

#### 语义颜色

- 采用随浅色、深色外观切换的语义 token，不在产品基线中锁定固定色值；
- 基础语义至少包括背景、前景、次要文字、分隔线、选中、焦点和破坏性状态；
- 正常状态保持中性；本地草稿、已应用等持续状态采用克制的邻近标签或结果信息；
- 只读、不兼容、漂移、冲突和写入阻断等会改变判断的状态提升视觉权重，但颜色必须同时配合图标、文字或形状；
- 选中态与风险态使用不同语义：选中态表达当前位置，风险态表达需要判断或处理，不能共用同一套强调。

#### 间距、密度与结构

- 使用 4 px 基础网格，常用间距为 8、12、16 和 24 px；
- 常用控件基准约 32 px 高；资产列表保持约 44 px 的固定两行信息增强行；
- 工作区以 1 px 中性分隔线组织结构，不通过大面积卡片、重阴影或装饰性色块切割主界面；
- 小圆角只用于控件、状态标签和聚焦确认等明确边界，结构面板继续保持薄界面；
- 当空间不足时，继续按已确认的面板收拢顺序保护原生内容，不通过压缩字号或缩小核心命中区域换取密度。

#### 状态与图标

- 正常磁盘内容不常驻状态标签；本地草稿在文件或路径上下文附近持续同位显示；
- 只读或不兼容状态弱化不可用操作，并在邻近位置提供可读原因；不能只依赖禁用外观；
- 漂移提供图标、文字及邻近处理入口；冲突使用破坏性语义并进入三方差异，始终阻断静默覆盖；
- 应用成功、失败或回滚均在原位展示结果；成功状态同时提供本次恢复点，不只依赖短暂提示；
- 使用 16 px 线性图标；关键操作始终保留可见文字，只有约定俗成的次要操作可以使用纯图标按钮，并提供完整无障碍名称；
- 收拢资产列表继续使用 `Library`，辅助检查器继续使用 `PanelRightOpen`，不重新打开已确认的角色映射。

#### 焦点、对比与动效

- 保留系统或平台原生焦点环，所有键盘可操作元素都必须具有清晰焦点，不移除焦点样式；
- 正文文本对比度目标至少为 4.5:1；关键非文本信息与焦点指示目标至少为 3:1；
- 颜色不作为唯一状态线索；图标、文字、形状或位置至少提供一种同步线索；
- 局部面板切换、覆盖式浮层和轻量反馈复用已确认的 160 ms 节奏，不使用循环或装饰性动效；
- 尊重系统“减少动态效果”设置，启用时直接切换最终状态，不以动画作为理解流程的必要条件。

该规范继续贯彻“原生内容视觉主导”：资产列表、文件树、工具栏、状态和检查器只提供完成判断与安全操作所需的辅助层级，不建立第二个视觉中心。
